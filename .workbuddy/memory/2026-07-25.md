- **键盘左右箭头无法翻页 Bug「搜索框选中后每次打开都残留焦点，吞掉左右箭头」**：
  **根因**：`LaunchpadWindowController.setupKeyMonitor` 里有 `if self.isTextInputFirstResponder() { return event }`——**无条件**把所有按键交还输入框。而 `panel`/`NSHostingView` 在 `show()` 时**复用不重建**→ `SearchBarView` 的 `@FocusState private var isFocused` 跨 `hide()/show()` 保留；`hide()` 只清 `searchText=""` 但**没让搜索框失焦**→ 重新 `show()` 后 field editor 仍是 firstResponder → `isTextInputFirstResponder()` 一直 true → 左右箭头（case 123/124）被直接 return 吞掉，永远走不到 `goToPreviousPage/NextPage`。`isSearching` 本身随 searchText 同步（清空即 false），所以不是搜索态卡住，而是**焦点残留导致的按键吞噬**。

- **拼音输入分裂 Bug「打 haima 拼音，h 进一处、aima 进另一处」(上一轮「失焦修复」引入的回归)**：
  **根因**：上轮为修「箭头被吞」在 `LaunchpadView` `show()` 时强制 `searchFocused = false`，导致**搜索框永远不自动聚焦**。于是打开启动台打拼音时：首字母 `h` 因搜索框无焦点 → 被键盘 monitor `default` 分支直接 `searchText += "h"`（绕开输入框）；后段 `aima` 由系统拼音 IME 在发现窗口有 TextField 后写回输入框本身。两套写入机制同时作用于 `searchText` → 分裂（"h 一个、aima 一个"）。
  **修法（组合，既要 IME 不分裂、又要翻页不被吞）**：
  ① `LaunchpadView.swift` `show()` 聚焦：`onChange(of: viewModel.isVisible) { if visible { searchFocused = false; DispatchQueue.main.async { searchFocused = true } } }`——先 false 再 async true，确保 panel/NSHostingView 复用（不重建）时 SwiftUI @FocusState 能真正重新聚焦（直接 true 因值未变可能不 re-apply）。
  ② `LaunchpadWindowController.swift` `setupKeyMonitor` 重写焦点门控：
    ```
    let focused = self.isTextInputFirstResponder()
    let isPrintable = (event.characters?.isEmpty == false) && !cmd/ctrl/opt
    if focused {
        if viewModel.searchText.isEmpty {
            if isPrintable { return event }   // 聚焦且空：可打印字符交还输入框，让 IME 从首字母起在 firstResponder 上下文合成
        } else {
            return event                       // 聚焦且有内容：全部交还输入框（光标/删除/IME）
        }
    }
    // 未聚焦：走下方字母搜索/导航
    ```
  **关键不变量**：搜索框**必须在 show 时聚焦**（与原生 Launchpad 一致），否则拼音 IME 必分裂；monitor 在「聚焦且空」时**可打印字符须交还输入框（return event）而非自行 `searchText +=`**，否则首字母被截走、其余被 IME 写回 → 分裂。方向键/ESC 仍落入下方导航逻辑 → 翻页不被吞（上轮箭头 bug 仍有保障）。
