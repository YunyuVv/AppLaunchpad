## 修复：拖到 appB 上 appB 弹簧让位后弹回原位（make-way 常驻）

- 现象（用户反馈）：拖 appA 到 appB 时 appB 让位弹簧，但无法在 appB 原本位置落位——一压到 appB 图标上 appB 就弹回原位。期望：appB 保持被推开、appA 可在 appB 原位置落位；仅当 appA 被拖离时 appB 才归位。
- 根因：`DragController.pageItemsWithDrag` 在 `folderDropTargetID/folderHoverID` 置位时直接 `return data.layout.pages[pageIndex]`（返回原始排列），等于悬停建文件夹/归入时强制停掉全部让位 → appB 弹回原位。
- 修复：
  1. `DragController.pageItemsWithDrag` 删除该早期返回，实时让位(make-way)始终开启。建/归入判定只改「松手语义」与高亮（蓝圈/白环），不再让目标弹回。压图标→松手建文件夹、压间隙→重排，二者都保持 appB 被推开；仅 `cursorSlot` 变化(appA 拖离)时 appB 才归位。
  2. `FolderController.createFolder` 修正同页建文件夹重复 bug：原先仅在跨页(`srcPage != pageIndex`)时移除被拖 app，同页时残留 → 网格里 1 份 + 文件夹里 1 份。改为统一从被拖 app 当前所在页移除后再建文件夹。
- 验证：`xcodebuild -project AppLaunchpad.xcodeproj -scheme AppLaunchpad -configuration Debug build` → **BUILD SUCCEEDED**。
- 待真机实测：拖 A 到 B 上 B 不弹回、可在 B 原位置落位；压图标松手建文件夹(同页/跨页均无重复)；压文件夹松手归入；拖离后 B 归位。

## 修复：拖拽松手"落不到正位 / 有点偏离 / 还回去了"

- 现象（用户反馈）：app 拖拽移动后无法正常落位——"落不到正位，有点偏离"，且有时"点击其他地方还回去了"。
- 根因（两类）：
  1. **松手落点用最后一次 `onChanged` 的 `cursorSlot`**：SwiftUI `DragGesture.onEnded` 不保证松手瞬间再触发 `onChanged`，光标最后一段位移（尤其快速拖动松手）会让 `cursorSlot` 落后一格 → 落点偏移一格。
  2. **FSEvents 刷新与拖拽并发**（审计报告 4.5）：`saveLayout` 写盘或系统文件事件触发 `refreshApps()` 重建 `layout.pages`，若发生在拖拽途中会让 `sourceSlotIndex`/`cursorSlot` 失效，落点错乱甚至把刚排好的顺序冲掉（表现为"拖完被弹回/还回去")。
- 修复：
  1. `LaunchpadView.globalDragGesture.onEnded`：松手前先 `viewModel.updateDragTarget(location: value.location)` 用松手精确坐标重算 `cursorSlot`，再 `endDrag()`。
  2. `DragController.endDrag` 重排分支：以 `geo.slotUnderCursor(data.dragState.dragLocation)` 兜底重算 `to`（双保险，即使 onEnded 未重算也对）。
  3. `LayoutService.refreshApps`：拖拽中(`data.dragState.isDragging`)直接置 `data.pendingAppsRefresh = true` 并跳过重建，避免索引失效。
  4. `LaunchpadData` 新增 `@ObservationIgnored var pendingAppsRefresh`，`DragController` 新增 `layoutService` 依赖；`endDrag` 复位 `dragState` 后若 `pendingAppsRefresh` 则 `Task { await layoutService.refreshApps() }` 补执行（保留刚排好顺序）。
  5. 组合根 `LaunchpadViewModel.init` 传 `layoutService` 给 `DragController`。
- 验证：`xcodebuild … Debug build` → **BUILD SUCCEEDED**。
- 待真机实测：快速拖动松手落点紧跟光标不偏一格；拖拽途中触发文件事件不再让 app 弹回原位。

## 回归修复：GridPageView 丢 cellW×cellH 固定框 → 布局乱 / 不全屏 / 拖拽对不上

## 修复：拖拽落位不准 + 松手后"无法点击 / 需先点别处"（手势闭包局部变量被 body 重算吞掉）

- 现象（用户反馈，紧接上轮重构后）：①移动"比较舒服了"（make-way 正常），但"鼠标松开的时候 要落到附近的位置上吧, 当前没有正确落位"；②"且鼠标松开的时候 无法点击了 需要点击一下其他地方,才能再次移动其他app"——点击一下背景（= `exitEditMode`）就恢复了。
- 根因（**两个问题同一根因**）：`LaunchpadView.globalDragGesture` 是个**计算属性**，把 `hasCheckedStart` / `startBundleID` 这两个关键状态用**局部 `var` 捕获**在闭包里。由于 `@Observable` 在拖拽中（`dragLocation` / `isDragging` / `floatingDragIcon`）频繁触发 `body` 重算，该手势每次都被**重新创建** → 闭包局部变量重置。
  - 拖拽起手后 `beginDrag` 改 `dragState.isDragging=true` → `body` 重算 → 手势实例被换掉；
  - 松手时 `onEnded` 跑在**新实例**上，新实例的 `startBundleID` 是 `nil` → `guard startBundleID != nil` 失败 → **`endDrag()` 从未执行**；
  - 后果 ①：app 落位与预览"零跳变"承诺失效——`endDrag` 没跑 = 没重排 = app 视觉上"弹回原位"（用户看到"没有正确落位"）。
  - 后果 ②：`dragState.isDragging` 卡在 `true`，`pagingDragGesture` 的 `!viewModel.dragState.isDragging` 守卫挡掉所有翻页/点击；点击背景 = `exitEditMode()` 把 `dragState = DragState()` 复位 → 卡死解除 → 下次拖拽（碰巧时机对了）又能动（典型"时灵时不灵"）。
- 修复：用 **`@GestureState`**（视图级、跨 body 重算保留，且专为拖拽设计——写它不会中断手势）替代闭包局部变量。`@GestureState` 通过 `.updating($dragStart) { value, state, _ in ... }` 写入，在 `onEnded` 时仍可读（手势结束后才自动复位）。`onChanged` 的副作用（`beginDrag`/`updateDragTarget`）依然触发 `@Observable` 重渲染 → 手势重建 → 但 `dragStart` 是视图级状态，重建后新闭包继续持有正确的 `checked/bundleID`。
  - 改动：`LaunchpadView` 顶部新增 `@GestureState private var dragStart: (checked: Bool, bundleID: String?) = (false, nil)`；`globalDragGesture` 改用 `.updating($dragStart)` 写状态；`onEnded` 读 `dragStart.bundleID`（不再用局部 var）。`pagingDragGesture` 没用闭包局部变量，无需改。
- 验证：
  1. `xcodebuild … Debug build` → **BUILD SUCCEEDED**。
  2. 临时加回 `--show-launchpad` 自动显示开关 + `screencapture` 启动 app 截图：9×5 均匀网格、4 页指示、布局与上一轮一致，**`@GestureState` 改动无渲染回归**。截图 `/tmp/lp.png`。
  3. 已删除临时调试开关，重新编译 **BUILD SUCCEEDED**。
- 待真机实测（需要真实鼠标拖拽，截图无法验证）：
  - 连续多次拖不同 app → 每次松手都**正常落位到光标附近**（无"弹回原位"）；
  - 松手后**立刻再点另一个 app 拖动** → 第一次点击就生效（不再"先点别处"）；
  - 快速拖动松手仍紧跟光标（上轮 `updateDragTarget(value.location)` 兜底仍生效）。
- 同步 MEMORY.md 新增红线："拖拽/翻页手势的"跨闭包持久状态"必须放 `@State` 或 `@GestureState`，绝不可放计算属性闭包的 `var`（body 一重算就被吞，导致 onEnded 跑在新实例上、guard 失败、行为丢失）"。

## 修复：松手"停留在这个地方、没落在正中心"（transition 渐隐残影 + 让位 spring 双重作用）

- 现象（用户截图反馈，紧接上轮 @GestureState 修复后）：松手后 app 图标停留在光标附近（截图里 AiPromptHub 图标浮在第一行与第二行之间的间隙），没移到 cell 中心。
- 根因（两层动画叠加导致"渐隐残影"）：
  1. `floatingDragIcon` 用了 `.transition(.opacity)`——松手时 `dragState.isDragging=false` 触发 view 移除，配合外层 `.animation(.spring, value: cursorSlot)` 在松手瞬间（cursorSlot 重置为 0）启动 spring → transition 渐隐 ~0.35s。**期间浮动图标仍渲染在光标位置**（用户松手时光标停在两行间隙），就是用户看到的"绿色图标浮在附近"。
  2. `GridPageView.body` 的 `.animation(.spring, value: dragState.cursorSlot)` 在松手瞬间 cursorSlot 从让位值变 0 触发整网 spring——但让位布局与 endDrag 写入的最终布局顺序一致（都是 insert at to），items 数组其实不变；问题主要是 transition 在 spring 周期内被驱动。
- 修复（让 spring 统一驱动整段落位过程，避免 transition 残影）：
  1. `LaunchpadView.body` 在根视图层加 `.animation(.interactiveSpring(response: 0.35, dampingFraction: 0.82), value: viewModel.dragState.isDragging)`——让松手时 iconCell 让位回位 + floatingDragIcon transition 移除被同一段 spring 驱动，浮动图标朝目标 cell 弹性滑过去再渐隐（与原生 Launchpad 视觉一致）。
  2. `LaunchpadView.globalDragGesture.onEnded` 用 `withAnimation(.interactiveSpring(response: 0.35, dampingFraction: 0.82))` 包裹 `viewModel.endDrag()`——确保 items 数组变化（持久化重排）与 dragState 复位在同一动画内。
  3. `GridPageView.body` 的 `.animation(.spring, value: dragState.cursorSlot)` 改为 `.animation(.spring, value: items)`——让位布局 = 最终布局（insert at to 顺序一致）→ 松手瞬间 items 数组不变 → spring 不再触发 → 无残影。拖拽中 items 变化时仍正常触发让位。
- 验证：
  1. `xcodebuild … Debug build` → **BUILD SUCCEEDED**。
  2. 临时加 `--show-launchpad` 启动 app + `screencapture` 截图 `/tmp/lp.png` → 9×5 网格正常、AiPromptHub 图标在 cell 顶部 / 标题在 cell 底部（与原生 Launchpad 一致）、无错位无残影。冒烟通过。
  3. 删除临时调试开关、最终编译 **BUILD SUCCEEDED**。
