## 拖拽起点 bug 修复：间隙里也能拖起 app（BUILD SUCCEEDED）

现象：拖 app 时鼠标必须压在 app 上才能拖；落在 cell 间隙里拖不动，此时左右滑动会翻页——用户判定为 bug。

### 根因
`LaunchpadView.globalDragGesture` 起点判定用 `viewModel.slotAt(startLocation)`（`slotAt` 要求坐标落在某槽位 frame 内才返回）。间隙不在任何 frame 内 → 返回 nil → 不启动拖拽；间隙区域的滑动事件落到背景层 `pagingDragGesture` → 翻页。

### 修复
1. `LaunchpadViewModel` 新增 `gridBounds`（所有 slotFrames 并集，全局坐标）+ `isPointInGridBounds(_:)`：网格范围含 cell 间隙，外边距/搜索栏/分页点在范围外。
2. `globalDragGesture` 起点判定改为：`isPointInGridBounds` 成立时取 `nearestSlot`（最近槽位）抓 app，间隙也能拖起最近的 app；仅当最近槽位是 app 才 `beginDrag`（folder 不网格内拖动，保点击打开）。起点在网格外则不启动拖拽。
3. `pagingDragGesture` 改用 `.global` 坐标并加 `!isPointInGridBounds(startLocation)` 守卫：起点在网格内（含间隙）直接让行（重置 dragOffsetX、不偏移、不翻页），彻底消除与拖拽手势的冲突/错位。网格外滑动仍可翻页；拖 app 到屏幕边缘自动翻页（edgeScrollTimer）与分页点点击照旧。

### 验证
`xcodebuild … Debug build` → **BUILD SUCCEEDED**。需真机实测：间隙起手拖最近 app、网格内滑动不再误翻页、网格外滑动仍能翻页、搜索框/分页点不受影响。
