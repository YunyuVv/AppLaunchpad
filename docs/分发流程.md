# AppLaunchpad 分发流程（步骤清单）

> 本文是**可执行的分发步骤流程**。背景知识与方案对比见 [`技术实现/05-分发与签名.md`](./技术实现/05-分发与签名.md)，技术红线见 [`开发指南.md`](./开发指南.md)。
> 目标：把本机开发中的 App 变成可发给其他 macOS 用户、**双击即运行、无需手动绕过 Gatekeeper** 的发布包。

---

## ⚠️ 0. 分发前必须先解决的两件硬性前置

不做这两步，分发到别人机器上**必然**出现"无法验证开发者"或被 GPL 传染风险。

### 0.1 版权红线：外观三卡片的 HEIC 资源（GPL v3）

- **现状**：`AppLaunchpad/Assets.xcassets/Appearance{Light,Dark,Auto}.imageset/*.heic` 三张图，是从开源项目 **LaunchNext 直接复制**的。LaunchNext 采用 **GPL v3（强 copyleft）**。
- **风险**：若以**闭源 / 商业**方式分发本 App，复用 GPL v3 资源会触发**许可证传染**——法律上也要求你公开整个 App 的源码。
- **必须二选一**（在打第一个发布包之前定案）：
  | 选项 | 做法 | 适用 |
  |---|---|---|
  | A. 替换为自制资源 | 删掉这三张 HEIC，改用自制等效图 / 自绘 SwiftUI 视图（备用生成脚本 `/tmp/AppearanceThumbnailGenerator.swift` 可改成输出本项目自有图） | **闭源 / 商业分发（推荐）** |
  | B. 整体开源 | 把整个 App 以 GPL v3（或兼容）开源，并在仓库附 `LICENSE` 与版权声明 | 仅做开源分发 |
- **结论**：要走"公开发布给普通用户"的路线，**必须先完成 A**（或 B）。否则不要进入第 1 步之后的流程。

### 0.2 证书切换：Apple Development → Developer ID Application

- **现状**（`project.yml`）：`CODE_SIGN_IDENTITY: "Apple Development"` + `DEVELOPMENT_TEAM: 2VU69Q9CGK`。这是**开发证书**，签名产物只能在本机 / 同 Team 设备运行，无法分发给他人。
- **分发要求**：必须用 **`Developer ID Application`** 证书签名（这是 Apple 专门给"店外分发"的证书），再加公证。
- **前置账号**：需加入 **Apple Developer Program（$99/年）**，且 Team 一致（Team ID `2VU69Q9CGK`）。
- 切换动作在第 2 步完成。

> 说明：当前 `entitlements` 已关闭沙盒（`com.apple.security.app-sandbox = false`）+ 开启 `automation.apple-events`。这是正确的——本 App 依赖全局快捷键、Accessibility、FSEvents，沙盒无法满足，因此**只能店外分发，不能上 Mac App Store**。见第 8 节。

## 1. 准备 Apple Developer 账号与证书

1. 确认已加入 Apple Developer Program（付费账号）。
2. 在 **Xcode → Settings → Accounts → 选中 Team `2VU69Q9CGK` → Manage Certificates** 中，确保存在：
   - **`Developer ID Application`** 证书（用于签名 .app）
   - （可选）**`Developer ID Installer`** 证书（若后续要打 .pkg 安装包）
3. 若没有，点 `+` 新建 `Developer ID Application`（Xcode 会自动向 Apple 申请并下载到钥匙串）。
4. 记录你的 **Apple ID** 和 **app-specific password**（苹果账号 → 登录与安全 → App 专用密码，用于第 5 步公证），以及 **Team ID = `2VU69Q9CGK`**。

---

## 2. 调整工程配置（分发态）

编辑 `project.yml`，把签名身份切到 Developer ID（其余保持 Manual / Team / hardened runtime / 无沙盒不变）：

```yaml
settings:
  base:
    CODE_SIGN_STYLE: Manual
    CODE_SIGN_IDENTITY: "Developer ID Application"   # 改这里（原为 "Apple Development"）
    DEVELOPMENT_TEAM: 2VU69Q9CGK
    PRODUCT_BUNDLE_IDENTIFIER: com.biliww.applaunchpad
    ENABLE_HARDENED_RUNTIME: YES                      # 必须，公证要求
    MACOSX_DEPLOYMENT_TARGET: "26.0"
    SWIFT_VERSION: 6.0
    SWIFT_STRICT_CONCURRENCY: complete
```

> ⚠️ 改了 `project.yml` 后**必须重新生成工程**：`xcodegen generate`（本会话红线：改 .yml / 增删 .swift 后必跑，否则找不到符号或配置不生效）。

**版本号提升**（`AppLaunchpad/Info.plist`）：首次公开发布建议 `CFBundleShortVersionString` 从 `0.1.0` 提到 `1.0.0`，`CFBundleVersion` 递增（如 `1`→`2`）。每次发布都应递增 `CFBundleVersion`，便于崩溃符号匹配与公证去重。

**版权字符串**（`Info.plist` 的 `NSHumanReadableCopyright`）确认无误（当前为 `Copyright © 2026 AppLaunchpad`）。若选了 0.1 的"开源"路线，这里改为对应许可证声明。

---

## 3. 构建 Release Archive

方式一（命令行，可在本机用正常 Xcode，无需关沙箱）：
```bash
xcodegen generate
xcodebuild -project AppLaunchpad.xcodeproj -scheme AppLaunchpad \
  -configuration Release archive \
  -archivePath ./build/AppLaunchpad.xcarchive
```

方式二（Xcode GUI）：`Product → Archive`（Scheme=AppLaunchpad，构建配置=Release），在 Organizer 中生成 `.xcarchive`。

> 本开发容器因沙盒限制需关沙箱编译（见 开发指南.md 红线），但**你自己的 Mac 上正常 Xcode archive 即可，无需那套 hack**。

产物：`./build/AppLaunchpad.xcarchive/Products/Applications/AppLaunchpad.app`（已用 Developer ID 签名 + hardened runtime）。

---

## 4. 导出 .app（确认 Developer ID 签名）

用 `exportOptions.plist` 导出（推荐，Xcode 会正确处理嵌套组件签名）：

```xml
<!-- exportOptions.plist -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>method</key>
    <string>developer-id</string>
    <key>signingStyle</key>
    <string>manual</string>
    <key>teamID</key>
    <string>2VU69Q9CGK</string>
    <key>stripSwiftSymbols</key>
    <true/>
</dict>
</plist>
```

```bash
xcodebuild -exportArchive \
  -archivePath ./build/AppLaunchpad.xcarchive \
  -exportPath ./build/export \
  -exportOptionsPlist exportOptions.plist
```

导出后校验签名身份：
```bash
codesign -dv --verbose=2 ./build/export/AppLaunchpad.app
# 应看到 Authority=Developer ID Application: ... (2VU69Q9CGK)，且 `Runtime ` 标记存在（hardened runtime）
spctl -a -vv -t open --context context:primary-signature ./build/export/AppLaunchpad.app
# 应显示 accepted（尚未公证前可能提示需联网评估，属正常）
```

---

## 5. 公证（Notarization）

把 .app 先打成 zip（或 dmg，见第 6 步先打 dmg 再公证 dmg 也行；这里演示对 .app 公证）：

```bash
# 5.1 压缩以便提交
ditto -c -k --keepParent ./build/export/AppLaunchpad.app ./build/AppLaunchpad.zip

# 5.2 提交公证（约 1–5 分钟）
xcrun notarytool submit ./build/AppLaunchpad.zip \
  --apple-id "你的AppleID@example.com" \
  --team-id "2VU69Q9CGK" \
  --password "app-specific-password" \
  --wait

# 5.3 给 .app 附着公证票据（stapler 会从 Apple 拉取票据写入包内）
xcrun stapler staple ./build/export/AppLaunchpad.app

# 5.4 验证
xcrun stapler validate ./build/export/AppLaunchpad.app
spctl -a -vv -t open --context context:primary-signature ./build/export/AppLaunchpad.app
# 应显示 accepted
```

> 也可先打 dmg 再对 dmg 公证（`notarytool submit AppLaunchpad.dmg ...` + `stapler staple AppLaunchpad.dmg`），更常见。二选一即可。

---

## 6. 打包为 .dmg（分发包）

推荐用 `create-dmg`（或 `npm i -g create-dmg` / `brew install create-dmg`）生成带"拖到 Applications"快捷方式的安装盘：

```bash
create-dmg \
  --volname "AppLaunchpad" \
  --window-pos 200 120 \
  --window-size 500 320 \
  --icon-size 100 \
  --icon "AppLaunchpad.app" 125 150 \
  --app-drop-link 375 150 \
  ./build/AppLaunchpad.dmg \
  ./build/export/AppLaunchpad.app
```

然后对 **dmg 本身**再走一次第 5 步公证 + `stapler staple AppLaunchpad.dmg`（若第 5 步是对 dmg 提交的，则已在 dmg 上 staple）。

---

## 7. 分发与发布

- **GitHub Releases**：上传 `AppLaunchpad.dmg`（已公证），写 Release Notes（版本、更新内容、首次需授权 Accessibility 的提示）。
- **官网 / 网盘**：托管 dmg 下载链接。
- 用户下载后**双击 dmg → 拖入 Applications → 启动**，因已公证 + staple，**无"无法验证开发者"提示**，直接运行。

---

## 8. 首次运行权限（用户侧，必须告知）

本 App 依赖以下系统能力，**用户首次使用需在系统设置授权一次**（非证书/签名能替代）：

1. **辅助功能（Accessibility）**：用于全局快捷键（⌥+Space 唤起）、全局事件监听。
   - 路径：`系统设置 → 隐私与安全性 → 辅助功能 → 打开 AppLaunchpad`。
   - 因是 Developer ID 稳定签名，授权**跨版本升级持久有效**（不像 ad-hoc 每次重编译失效）。
2. **全盘磁盘访问（可选）**：若需扫描 `/Applications` 以外目录的 App，可能需 `完全磁盘访问权限`。
3. 建议在 App 内首次启动时**主动引导用户去系统设置授权**（弹窗 + 跳转到设置），降低支持成本。

---

## 9. 为什么不上 Mac App Store（MAS）

本项目**无法**走 Mac App Store，原因（均因需非沙盒能力）：

| 能力 | MAS 要求 | 本项目 |
|---|---|---|
| 沙盒 | 必须启用 | ❌ 已关闭（entitlements `app-sandbox=false`） |
| 全局快捷键 `addGlobalMonitorForEvents` | 沙盒下受限 | 依赖此能力 |
| Accessibility（唤起启动台） | 沙盒下需用户单独授权且受限 | 依赖此能力 |
| FSEvents 监听系统目录 | 沙盒下不可 | 依赖此能力 |

→ 结论：**只走 Developer ID + 公证的店外分发**（第 1–7 步）。

## 11. 回滚提示（分发后改回开发态）

发布完成后，把 `project.yml` 的 `CODE_SIGN_IDENTITY` **改回 `"Apple Development"`** 再 `xcodegen generate`，否则日常开发调试会用 Developer ID 证书（钥匙串里若是不同证书会编译失败，且 Developer ID 签名每次都要联网/公证不便于本地快速迭代）。开发期保持 Apple Development 是为了辅助功能权限持久（见 开发指南.md 红线）。
