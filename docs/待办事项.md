## A. 未完成功能

### A1. 右键菜单「添加到程序坞」（P0 缺口）— R3
- 原生启动台右键有「添加到程序坞」，本项目右键菜单目前是「打开 / 在 Finder 中显示 / 删除」，**无**此项目。
- 实现思路：读 `~/Library/Preferences/com.apple.dock.plist` 的 `persistent-apps`，追加 `file-tile`，`killall Dock`（放后台 Task 避免卡 UI）；按 path 去重。
- 参考：`docs/需求/App图标操作能力需求.md` R3（注：该文档声称文件夹"已移除"系误述，见下文一致性）。

### A2. 拖拽到程序坞（P2）— R5
- 从启动台把图标拖到 Dock 释放即加入。需接入 Dock 拖放事件（AppKit `performDragOperation`），工作量较大，可视 A1 后扩展。

### A3. 原生 Launchpad 布局导入（P0 待办）
- 把系统原生 Launchpad（`~/Library/Application Support/Dock/*.db` 或 `defaults read com.apple.dock` 的 `persistent-apps`）的布局导入本项目，减少冷启动后用户手动重排成本。
- 当前代码无 `NativeLaunchpadImporter`（仅在 `references/LaunchNext/` 参考项目里见类似实现）。
- 来源：`docs/技术实现/启动台功能梳理与技术方案.md` 标记为「⏳ 未做（P0 待办）」。

### A4. 编辑态图标抖动（WobbleModifier 已定义未接入）
- `Views/WobbleModifier.swift` 定义完整，但全代码库无 `.wobble(` 调用 → 编辑模式图标抖动动画当前**不生效**。
- 接入点：`AppIconView` / `FolderThumbnailView` 在 `isEditMode` 时附加 `.wobble()`。

### A5. 触摸板拖拽排序
- 当前仅支持**鼠标拖拽**排序；触摸板手势用于翻页，未用于拖拽重排。如需支持需区分拖拽手势来源。

## B. 待决策（当前代码不动，需用户拍板）

### B1. 键盘方向键 / 翻页行为
- 原生启动台：四方向键只做**页内高亮移动**，翻页仅触控板/点圆点，键盘不翻页。
- 当前实现：←/→ 翻页、↑/↓ 选择（偏离原生）。
- 选项：
  - **A 保持现状**（左右翻页+上下选择）
  - **B 对齐原生**（四方向都页内移动，键盘不翻页）
  - **C 现状 + 设置开关**（默认现状，可切原生）
- 详细分析见旧文档 `docs/待办/后续优化功能.md`（该文件仍有效，本文为其权威摘要）。

### B2. 删除入口双轨问题（待澄清）
- **现状**：既有 `AppIconView` 右键菜单「删除」，编辑模式也有删除 X（`AppIconView` 在 `isEditMode && onDelete != nil` 显示；`GridPageView` 传 `onDeleteApp`）。
- **历史决策**：用户曾表示"编辑模式 X 不好看"，改为右键菜单删除替代 X。但代码**仍保留**编辑模式 X。
- **待澄清**：是保留双轨、还是彻底移除编辑模式 X 仅留右键删除？需用户拍板后统一代码与文档。

## C. 已决策不做（沉淀，勿重复踩）

### C1. 设置窗口浮于启动台上方 + 启动台背景虚化
- **决策**：2026-07-25 用户回滚放弃（含本会话多方案尝试 + 之前"降面板 hack"基线，最终 20:19 连基线也移除）。
- **目标回顾**：让"设置"窗口稳定浮在启动台之上，并可选对启动台做背景虚化。
- **尝试过的 5 个方案与坑**（重要，未来若重做必须先读）：
  1. **降面板 hack（最早基线，已删）**：`AppDelegate` 监听全局 `didBecomeKey` → 设置窗口成为 key 时把启动台面板降到 `.normal`，关闭再升回。坑：依赖"成为 key 时序"有竞态，偶尔压不住；设置打开期间启动台键盘 monitor 仍在跑→ESC 误关/字母误入搜索；全局通知污染。
  2. **直接设层级**：`SettingsView` 加 `WindowLevelAccessor`(`NSViewRepresentable`) 在 `makeNSView` 里 async 拿 `view.window` 设 `level=.screenSaver`。坑：`.background` 子视图 `makeNSView` 时 `window==nil` → level **从未设置**，被面板压住（根本没浮起来）。
  3. **updateNSView + 抬窗**：把设 level 移到 `updateNSView`（视图已挂载、`window` 可靠），并监听 `didBecomeKey` 只升不降。仍不够稳。
  4. **原生 NSView 右键菜单**（顺带解决右键菜单弹不出）：`.contextMenu` 与同视图 `.simultaneousGesture(DragGesture)` 在 macOS 冲突→右键菜单弹不出。改用 `NSView.hitTest` 只拦右键/control+左键、左键拖拽透传。
  5. **手动托管 NSWindow**：弃用 `Window(id:)` 场景，`AppDelegate` 自建 `NSWindow`(`isReleasedWhenClosed=false`, `orderFront` 重开, `level=.screenSaver`)。坑：用户实测"先开设置再开启动台能浮；关闭设置后再右键打开打不开"——根因是 SwiftUI `Window(id:)` 场景关闭后 `openWindow(id:)` 重开不可靠（SwiftUI 已知 bug）；手动托管能解重开，但方案整体被否。
- **取舍结论**：独立不透明窗口浮层 → 虚化只在窗口四周边缘外可见（非整屏虚化）；overlay 浮层需丢系统标题栏（样式变化）。若未来重做，要么接受样式变化（overlay 进 `LaunchpadView` ZStack + `FolderBackdropView` 虚化），要么手动托管半透明窗口。
- **当前状态（2026-07-25 20:19 后）**：设置窗口 = 普通独立 SwiftUI `Window(id:"settings")` 场景，启动台面板仍是极高 `screenSaverWindow-1` 层级；启动台可见时开设置会落在面板之后（用户接受）。无层级 hack 代码残留。
