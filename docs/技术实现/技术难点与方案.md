## 二、各难点详细分析

### 难点 1：全屏窗口层级与键盘焦点管理

#### 问题描述

启动台需要：
- 覆盖所有窗口（包括全屏应用）
- 在展示时能接收键盘输入（搜索框、方向键、Escape）
- 关闭后不影响其他应用的焦点

若使用普通 `NSWindow`，层级不够；若设置太高的 level，会导致焦点混乱。

#### 解决方案

```swift
// 使用 NSPanel（非激活面板）
let panel = NSPanel(
    contentRect: screen.frame,
    styleMask: [.borderless, .nonactivatingPanel],
    backing: .buffered,
    defer: false
)
panel.level = NSWindow.Level(rawValue: Int(CGWindowLevelForKey(.screenSaverWindow)) - 1)
panel.collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary, .stationary]
panel.isFloatingPanel = true
panel.becomesKeyOnlyIfNeeded = false  // 允许成为 key window 接收键盘
```

**键盘焦点策略**：
1. 展示时调用 `panel.makeKey()` 让 panel 成为 key window
2. 搜索框使用 `@FocusState` 管理焦点
3. 按 Escape：先检查是否在搜索状态 → 若有搜索词则清空 → 否则关闭启动台
4. 关闭时 `panel.resignKey()` 并将焦点归还给原来的应用（记录 `NSWorkspace.shared.frontmostApplication`）

#### 风险应对

- macOS 26 可能调整窗口层级常量，需测试 `CGWindowLevelKey` 枚举值
- 全屏应用场景下（Mission Control space），需额外测试 `canJoinAllSpaces` 行为

### 难点 2：背景壁纸虚化效果

#### 问题描述

启动台背景需要显示当前桌面壁纸的虚化版本。直接截屏会带来隐私和性能问题。

#### 方案对比

| 方案 | 优点 | 缺点 | 结论 |
|-----|------|------|------|
| 截取屏幕图像 + Core Image 模糊 | 效果最真实 | 需要屏幕录制权限（macOS 10.15+） | ⚠️ 需授权 |
| 读取壁纸文件 + 模糊 | 不需要额外权限 | 无法反映动态桌面/多桌面状态 | ✅ 推荐 |
| `NSVisualEffectView` 直接用 | 系统原生，性能最优 | 效果固定，无法精确控制 | 可作为降级方案 |
| Metal Shader 实时模糊 | 高性能 | 开发成本高 | 不推荐 |

#### 推荐方案：读取壁纸 + 离线模糊

```swift
// 获取当前桌面壁纸路径
func currentWallpaperURL() -> URL? {
    NSWorkspace.shared.desktopImageURL(for: NSScreen.main!)
}

// 异步生成模糊背景
func generateBlurredBackground(from url: URL) async -> NSImage? {
    guard let ciImage = CIImage(contentsOf: url) else { return nil }
    let filter = CIFilter.gaussianBlur()
    filter.inputImage = ciImage
    filter.radius = 20
    guard let outputImage = filter.outputImage else { return nil }
    let context = CIContext()
    guard let cgImage = context.createCGImage(outputImage, from: ciImage.extent) else { return nil }
    return NSImage(cgImage: cgImage, size: NSScreen.main!.frame.size)
}
```

**降级处理**：若壁纸是动态壁纸（.heic序列）或纯色，回退到 `NSVisualEffectView`。

### 难点 3：触控板捏合手势全局监听

#### 问题描述

捏合手势需要在应用未激活时也能响应（启动台未显示时，用户在桌面捏合）。

#### 解决方案

```swift
// 监听全局 NSEvent（需要 Accessibility 权限）
class GestureMonitor {
    private var eventMonitor: Any?
    
    func startMonitoring(onPinch: @escaping (CGFloat) -> Void) {
        eventMonitor = NSEvent.addGlobalMonitorForEvents(
            matching: [.magnify]
        ) { event in
            // event.magnification < 0 为捏合（缩小），> 0 为展开（放大）
            onPinch(event.magnification)
        }
    }
}
```

**权限处理策略**：
1. 首次运行时检查 `AXIsProcessTrusted()`
2. 若无权限 → 显示引导提示，跳转系统偏好设置 → 辅助功能
3. 无权限时降级：禁用触控板手势，仅支持快捷键和 Dock 点击
4. 应用重启后重新检测权限状态

**阈值处理**：
```
累积 magnification 值，当 < -0.3（捏合幅度足够大）且持续时间 > 0.1s → 触发呼出
```

### 难点 4：图标拖拽排序（含跨页拖拽）

#### 问题描述

这是整个项目最复杂的交互。需要：
- 单页内图标位置实时重排（其他图标动态让位）
- 跨页拖拽（拖至屏幕边缘自动翻页）
- 拖入/拖出文件夹
- 排序结果持久化

#### 整体方案

采用自定义拖拽实现，**不使用 SwiftUI 原生 `onDrag/onDrop`**（原生方案不支持实时重排动画）。

**核心数据结构**：

```swift
struct DragState {
    var isDragging: Bool = false
    var draggedItemID: String?          // 被拖拽图标的 bundleID
    var dragLocation: CGPoint = .zero   // 当前拖拽位置
    var sourcePageIndex: Int = 0        // 来源页
    var targetPageIndex: Int = 0        // 目标页
    var targetSlotIndex: Int = -1       // 目标槽位（实时计算）
    var edgeScrollTimer: Timer?         // 边缘翻页计时器
}
```

**实现步骤**：

1. **长按进入拖拽状态**
   ```
   NSPressGestureRecognizer（0.1s 阈值，用于拖拽）
   → 进入 DragState，记录被拖图标
   → 被拖图标 zIndex 提升，scale 变为 1.15
   ```

2. **拖拽移动时实时计算目标槽位**
   ```
   拖拽位置 → 换算为网格坐标 → 计算最近槽位
   → 更新 layout（其他图标让位，触发 withAnimation 重排）
   ```

3. **边缘翻页检测**
   ```
   拖拽位置 x < 60pt  → 启动 edgeScrollTimer，每 0.8s 翻一页（向前）
   拖拽位置 x > W-60pt → 启动 edgeScrollTimer，每 0.8s 翻一页（向后）
   离开边缘区域 → 停止 Timer
   ```

4. **松开时落位**
   ```
   松开手势 → 停止 DragState
   → 将图标插入目标槽位
   → 原位置补位（其余图标前移）
   → withAnimation(.spring) 触发落位动画
   → LayoutStore.save()
   ```

5. **拖入文件夹**
   ```
   目标槽位是文件夹 → 文件夹图标高亮（scale 1.1 + 边框）
   松开 → 应用加入文件夹，从主网格移除
   ```

**SwiftUI 实现核心**（每个图标的位置由索引决定）：

```swift
// 计算图标的显示位置（根据当前 layout 中的实际槽位）
func iconPosition(for bundleID: String, in layout: [[String]]) -> (page: Int, slot: Int) {
    // 考虑 dragState 的影响，实时返回"视觉位置"
}
```

### 难点 5：文件夹展开/收起动画

#### 问题描述

点击文件夹时，需要从文件夹当前位置"放大展开"，动画过程中背景变暗，展开后可以滚动内部图标。

#### 解决方案

使用 SwiftUI **`matchedGeometryEffect`** 实现位置过渡：

```swift
@Namespace var folderNamespace

// 收起状态：文件夹缩略图
FolderThumbnailView(folder: folder)
    .matchedGeometryEffect(id: folder.id, in: folderNamespace)
    .onTapGesture { openFolder = folder }

// 展开状态（overlay/ZStack）
if openFolder?.id == folder.id {
    FolderExpandedView(folder: folder)
        .matchedGeometryEffect(id: folder.id, in: folderNamespace)
        .transition(.identity)  // 由 matchedGeometryEffect 控制
}
```

**展开尺寸**：
- 展开后宽度约 560pt，高度约 380pt
- 居中于屏幕（使用 `.frame(maxWidth: .infinity, maxHeight: .infinity)` + alignment）
- 背景：额外一层半透明黑色遮罩（`Color.black.opacity(0.4)`）

### 难点 6：图标抖动动画（随机相位）

#### 问题描述

编辑模式下所有图标需要"抖动"，但每个图标的抖动相位要随机，否则看起来像整体同步摆动。

#### 解决方案

```swift
struct WobbleModifier: ViewModifier {
    let isWobbling: Bool
    @State private var angle: Double = 0
    private let amplitude: Double = 2.5   // 摆动角度（度）
    private let speed: Double             // 随机速度，由初始化传入
    
    init(isWobbling: Bool) {
        self.isWobbling = isWobbling
        // 每个图标创建时随机化速度（影响相位偏移）
        self.speed = Double.random(in: 0.9...1.1)
    }
    
    func body(content: Content) -> some View {
        content
            .rotationEffect(.degrees(isWobbling ? angle : 0))
            .onAppear {
                guard isWobbling else { return }
                // 随机初始相位
                let initialDelay = Double.random(in: 0...0.3)
                withAnimation(
                    .easeInOut(duration: 0.12 * speed)
                    .repeatForever(autoreverses: true)
                    .delay(initialDelay)
                ) {
                    angle = amplitude
                }
            }
            .onChange(of: isWobbling) { _, wobble in
                if !wobble {
                    withAnimation(.easeOut(duration: 0.1)) { angle = 0 }
                }
            }
    }
}
```

### 难点 8：呼出/关闭过渡动画

#### 呼出动画设计

原生 Launchpad 的呼出效果是"图标从四面八方飞入并放大"，精确复现需要每个图标的起始位置计算（Dock 中的图标位置）。

**简化方案**（推荐）：
```
背景：透明度 0 → 1，模糊从 0 → 20，时长 350ms
图标整体：scale(0.5) + opacity(0) → scale(1.0) + opacity(1)，时长 350ms，spring 弹性
```

**进阶方案**（还原原生效果）：
```
通过 NSRunningApplication 获取 Dock 中各 app 的位置（需 Accessibility 权限）
各图标从 Dock 位置飞入到网格位置
成本较高，可作为 v2.0 功能
```

#### 关闭动画设计
```
点击图标关闭：
    被点击图标：scale(1.0) → scale(1.3) → 消失（100ms）
    其他图标：整体 scale(1.0) → scale(0.8) + opacity(0)，时长 250ms
    背景：虚化效果淡出，时长 300ms
```

### 难点 9：多显示器适配

#### 核心问题

- 确定在哪个显示器展示（主屏 or 鼠标所在屏）
- 每个显示器分辨率不同，图标列数需要动态计算

#### 解决方案

```swift
// 获取目标显示器
func targetScreen() -> NSScreen {
    let preference = UserPreferences.multiMonitorBehavior
    switch preference {
    case .primaryScreen:
        return NSScreen.main ?? NSScreen.screens[0]
    case .mouseScreen:
        let mouseLocation = NSEvent.mouseLocation
        return NSScreen.screens.first { screen in
            screen.frame.contains(mouseLocation)
        } ?? NSScreen.main ?? NSScreen.screens[0]
    }
}

// 动态计算列数
func columnCount(for screen: NSScreen) -> Int {
    let width = screen.visibleFrame.width
    switch width {
    case 1440...: return 7
    case 1280..<1440: return 6
    default: return 5
    }
}
```

**窗口尺寸**：始终使用 `screen.frame`（完整物理屏幕，含菜单栏和 Dock 区域），不使用 `visibleFrame`（不含 Dock/菜单栏区域）。

#### 方案

通过 `LSApplicationCategoryType`（`Info.plist` 中的分类键）获取应用类别：

```swift
// Info.plist 中的 LSApplicationCategoryType 值对应关系
let categoryNames: [String: String] = [
```

## 三、技术风险汇总与应对策略

| 风险 | 概率 | 影响 | 应对策略 |
|-----|------|------|---------|
| macOS 26 API 变化导致窗口层级失效 | 中 | 高 | 建立 API 隔离层，版本兼容检查 |
| Accessibility 权限被用户拒绝 | 高 | 中 | 功能降级：无触控板手势，仍可用快捷键 |
| 屏幕录制权限 | 高（若用截屏方案） | 中 | 改用壁纸文件直接模糊，不需要此权限 |
| 拖拽排序逻辑 Bug（图标错位） | 中 | 高 | 充分测试，增加布局一致性校验断言 |
| 图标缓存内存泄漏 | 低 | 中 | 使用 NSCache，设置总内存上限（50MB） |
| FSEvents 回调线程安全 | 中 | 中 | 所有 UI 更新严格限定在 @MainActor |
