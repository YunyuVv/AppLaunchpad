# 全局快捷键：实现与排查指南

**版本**: v1.0.0
**日期**: 2026-07-21
**适用范围**: AppLaunchpad 全局快捷键（呼出/收起启动台面板）

> **一句话结论**：能让全局快捷键正常工作的链路有 5 道关——**能录制 → 授权辅助功能 → 稳定签名 → 开关打开 → 监听随授权重建**。任何一道断掉都不会触发。本文给出每一关的坑、根因与修法，以及一套"测试触发 + 诊断计数"的自助排查流程。

---

## 一、功能架构

全局快捷键由三段代码协同：

| 模块 | 文件 | 职责 |
|------|------|------|
| 偏好存储 | `AppLaunchpad/Models/UserPreferences.swift` | 存 `hotkeyEnabled`、修饰键 `hotkeyModifiers`、键码 `hotkeyKeyCode`、`hotkeyKeyLabel`；提供 `setHotkey(from:)`、`resetHotkeyToDefault()` |
| 全局监听 | `AppLaunchpad/App/AppDelegate.swift` | `setupGlobalHotkey()` / `ensureGlobalHotkey()` 用 `NSEvent.addGlobalMonitorForEvents` 捕获 `.keyDown`，命中则 `toggle()` |
| 录制 UI | `AppLaunchpad/Views/Settings/SettingsView.swift` | `HotkeyRecorder` 用本地监听捕获按键；`HotkeyPane` 展示/录制/测试/诊断 |

数据流：

```
用户按 ⌥C（任意 App 焦点）
  → 系统把 keyDown 派发给全局监听（需辅助功能权限）
  → AppDelegate 闭包比对 keyCode + 修饰键
  → 通过 guard → (NSApp.delegate as? AppDelegate)?.toggle()
  → 启动台面板弹出/收起
```

## 二、五道关：每一关的坑与修法

### 关 1：能录制（之前根本录不了）

**问题**：早期 `HotkeyPane` 只有"显示当前快捷键 + 恢复默认"按钮，没有任何录入入口，用户无法修改。

**修法**：
- `UserPreferences.setHotkey(from:)`：从 `NSEvent` 取 `keyCode` 与修饰键（剔除 Caps Lock 等无关修饰键）。
- `SettingsView.HotkeyRecorder`（`@MainActor ObservableObject`）：用 `NSEvent.addLocalMonitorForEvents` 捕获下一次 `keyDown`；Esc 取消；纯修饰键忽略；捕获后回传 `onCapture`。
- 设置面板"设置快捷键…"按钮进入录制态。

### 关 2：辅助功能授权（开发版找不到 App）

macOS 安全限制：**任何 App 都不能用代码把自己写进辅助功能白名单**，只能用户手动勾选。开发版是 ad-hoc 签名、藏在 DerivedData 里，去列表里根本找不着。

**修法**（一键触发 + 直接跳页 + 定位文件）：
- 主按钮「一键添加辅助功能权限…」：
  - `AXIsProcessTrustedWithOptions(["AXTrustedCheckOptionPrompt": true] as CFDictionary)` 让系统把本 App 登记进列表并弹授权提示；
  - 再 `NSWorkspace.open(URL(string: "x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility"))` 跳到设置页。
- 次按钮「在访达中显示 App」：`NSWorkspace.shared.activateFileViewerSelecting([Bundle.main.bundleURL])`，方便把 DerivedData 里的 `.app` 直接拖进列表。
- 实时状态灯：`TimelineView(.periodic(by: 1.0))` 每秒刷 `AXIsProcessTrusted()` → 绿点"已授权"/红点"未授权"。

> ⚠️ 踩坑：`kAXTrustedCheckOptionPrompt` 全局变量在 Swift 6 strict concurrency 下报"shared mutable state"不安全，改用字面值键字符串 `"AXTrustedCheckOptionPrompt"`。`.foregroundStyle(granted ? .secondary : .red)` 因 `.secondary`(层级样式) 与 `.red`(Color) 类型不一致报错，统一用 `Color.secondary` / `Color.red`。

### 关 3：稳定签名（反复失效的真凶）

**这是最致命的一关。** 表现：系统设置里辅助功能已"打开"、状态灯却仍显示"未授权"，重启也没用。

**根因**：之前编译一直带 `CODE_SIGN_IDENTITY=- AD_HOC_CODE_SIGNING_ALLOWED=YES`，把 `project.yml` 的 `CODE_SIGN_STYLE: Automatic` 覆盖成了 **ad-hoc 签名**。ad-hoc 签名的 TCC 指定要求（designated requirement）**包含二进制哈希**，每次 `xcodebuild` 重编译哈希就变 → 辅助功能等权限绑定的旧签名失效，新签名未被授权 → `AXIsProcessTrusted()` 恒为 false。你在列表里"打开"的那条是旧签名，和当前运行进程对不上。

**修法**：机器本就有 `Apple Development` 证书，无需自签。把稳定签名固化进 `project.yml`：

```yaml
settings:
  base:
    CODE_SIGN_STYLE: Manual
    CODE_SIGN_IDENTITY: "Apple Development"
    DEVELOPMENT_TEAM: 2VU69Q9CGK   # 真实团队 ID = cert subject 的 OU，不是名字括号里的串
```

- **注意**：真实团队 ID 是证书 subject 里的 `OU=2VU69Q9CGK`，名字括号里的 `A9H8HV4M63` 不是 team；传错 team 会报 `No certificate for team ... found`。
- `xcodegen generate` 重新生成 `AppLaunchpad.xcodeproj`。
- 证书签名后的 designated requirement 只绑 `identifier "com.applaunchpad.app"` + 证书 leaf CN + Apple 开发者字段，**不含二进制哈希** → 重编译后 TCC 完全一致，权限持久。验证：`codesign -d -r- AppLaunchpad.app` 看到 requirement 不含 hash 即正确。
- 最后 `tccutil reset Accessibility com.applaunchpad.app` 清掉旧 ad-hoc 授权残留，用新签名 App 重新授权一次（之后即稳定）。

**今后编译命令（务必遵守）**：

```bash
xcodebuild -project AppLaunchpad.xcodeproj -scheme AppLaunchpad -configuration Debug clean build
```

> 🚫 **不要再带** `CODE_SIGN_IDENTITY=- AD_HOC_CODE_SIGNING_ALLOWED=YES`，否则又回到 ad-hoc 老坑，权限再次失效。

### 关 4：开关默认打开

**问题**：就算监听能收到按键，`setupGlobalHotkey` 的 `guard` 含 `prefs.hotkeyEnabled`，而 `hotkeyEnabled` 默认 `defaults.bool(...) = false`（"启用快捷键呼出启动台"默认关），guard 直接 return，`toggle()` 从不调用。

**修法**：
- `UserPreferences.hotkeyEnabled` getter 改为"未显式设置时默认 true"（用 `defaults.object(forKey:) != nil` 判断，尊重用户后续显式关闭）。
- 设置面板关闭开关时显示橙色提示，避免困惑。

### 关 5：监听随授权/开关重建

**问题**：全局监听在 App 启动时建立。若辅助功能是在 App 已运行期间才授予、或"启用"开关在运行期间才打开，监听仍是 `nil`/旧状态（macOS 常见需重建或重启才生效），按快捷键无反应。

**修法**：`AppDelegate.ensureGlobalHotkey()` 改为"先 `remove` 旧监听再 `setupGlobalHotkey`"（幂等重装），在以下时机调用：
- `HotkeyPane` `.onAppear`（打开设置即重建）
- `.onChange(of: prefs.hotkeyEnabled)`（开开关即时生效）
- 「测试触发」按钮（见下）

## 三、修饰键陷阱：大小写无关，但 Shift 是修饰键

用户常问："opt+c 的 c 要大写吗？"

- **大小写无关**：快捷键按物理键 keyCode 判定，`C` 和 `c` 是同一键（keyCode 都是 8），`⌥+C` 与 `⌥+c` 触发的键码完全相同。
- **但 Shift（⇧）是修饰键**：若录制时为打"大写 C"而按了 Shift，存进去的是 `⌥+⇧+C`，之后只按 `⌥+c`（没按 Shift）修饰键对不上 → **不触发**。

**显示误导修复**：早期 `setHotkey` 用 `charactersIgnoringModifiers?.uppercased()` 作标签，`⌥+C` 实际打出 `©`，易让人误以为要大写。改为 `keyCodeToLabel()`：键码 0–25 → A–Z，其余走 `keyName` 兜底（F1–F12、方向键、Tab、Esc、空格等）。现在显示干净的 `⌥C`。

> ✅ **判定标准**：看设置 → 快捷键 → "当前快捷键"显示。
> - `⌥C` → 录制正确；
> - `⌥⇧C` → 录制时带了 Shift，重录（不按 Shift）；
> - `⌥空格` → 录制没生效，重录一次。

## 四、自助排查：测试触发 + 诊断计数

`HotkeyPane` 提供两个工具，无需重启即可定位断点：

1. **「测试触发」按钮**：重建监听 + 直接 `toggle()` 呼出面板。用于确认面板本身能开（`toggle()/show()` 链路）。
2. **实时诊断计数**（每秒刷新）：
   - `监听收到按键 N 次`（`hotkeyMonitorFiredCount`：每次 keyDown +1）
   - `匹配并触发 N 次`（`hotkeyMatchedCount`：guard 全通过才 +1）

### 排查决策表

| 现象 | 结论 | 处理 |
|------|------|------|
| 点「测试触发」面板能开，但按 ⌥C 无反应 | `toggle()` 正常，问题在全局监听 | 见下 |
| "收到"不涨 | 监听根本没收到按键 | 关闭设置窗口再打开一次（重建监听）；或别的 App 抢占了 ⌥C（换成 ⌥R 等冷门键） |
| "收到"涨、"触发"不涨 | 收到事件，但修饰键/键码没对上 | 看"当前快捷键"是否 `⌥C`；若显示 `⌥⇧C` 重录（不按 Shift） |
| 两个都涨、面板弹出 | 一切正常 ✓ | 享受 |

## 五、标准排查顺序（给最终用户）

1. 打开 **设置 → 快捷键**，确认「启用快捷键呼出启动台」开关是**开**的（新装默认即开）。
2. 看「当前快捷键」显示是否为期望组合（如 `⌥C`），且无多余 `⇧`。
3. 看辅助功能状态灯是否**绿**。若红：点「一键添加辅助功能权限…」→ 系统设置里把 `AppLaunchpad` 开关打开 → **⌘Q 完全退出**，重开一次（TCC 在进程启动时判定）。
4. 在别的 App（如桌面/浏览器）按快捷键，盯诊断计数：
   - 都涨 → 成功；
   - "收到"不涨 → 关闭设置窗口再开（重建监听）；
   - "收到"涨但"触发"不涨 → 重录（注意别带 Shift）。
5. 仍不行：菜单栏图标 →「打开启动台」能用吗？能用说明 `toggle()` 没问题，只剩监听一环，多半需重启让新签名监听生效。

## 七、FAQ

**Q：为什么我在系统设置里明明打开了，状态灯还是红？**
A：TCC 在进程启动时判定。你是在 App 已运行期间打开的，当前进程是"未授权"状态启动的。必须 ⌘Q 完全退出并重开。

**Q：重编译后又要重新授权，烦死了？**
A：因为之前是 ad-hoc 签名。按"关 3"固化 `Apple Development` 证书后，重编译权限持久，不再需要反复授权。

**Q：opt+c 要按大写吗？**
A：不用，大小写无关；但别顺手按 Shift，否则存成 ⌥⇧C 反而不匹配。

**Q：按了完全没反应，连"收到"计数都不涨？**
A：监听没收到事件。先关设置窗口再打开一次（触发 `ensureGlobalHotkey` 重建）；若仍不涨，多半是别的程序占用了 ⌥C，换个冷门组合键最省事。
