# 功能实现计划

**版本**: v1.0.0  
**日期**: 2026-07-20  
**关联需求**: PRD-启动台需求文档.md

---

## 一、实现原则

1. **由骨架到血肉**：先跑通整条链路（扫描→展示→启动），再逐层叠加交互细节
2. **先 P0 后 P1**：每阶段只做当前阶段必须的事，不提前实现后续阶段功能
3. **高风险优先验证**：全屏窗口层级、Accessibility 权限等不确定因素在早期阶段验证，避免后期返工
4. **可演示驱动**：每个阶段结束后应用必须可以正常演示，不留半成品

### Phase 1：工程基础

**目标**：应用能启动，能扫描到本机所有 App，能全屏展示图标网格，点击图标能打开对应应用。

#### 任务清单

| # | 任务 | 涉及文件 | 说明 |
|--|-----|---------|------|
| 1.1 | 创建 Xcode 工程 | `AppLaunchpad.xcodeproj` | macOS App，SwiftUI + AppKit，最低 macOS 26，关闭沙盒，配置 Entitlements |
| 1.2 | AppDelegate 基础骨架 | `AppDelegate.swift` | 接管 App 生命周期，设置 `activationPolicy = .accessory` |
| 1.3 | NSPanel 全屏窗口 | `LaunchpadWindowController.swift` | 创建铺满全屏的 NSPanel，验证层级覆盖效果 |
| 1.4 | LaunchpadViewModel 骨架 | `LaunchpadViewModel.swift` | `@Observable`，定义 `allApps`、`isVisible` 基础状态 |
| 1.5 | AppInfo 数据模型 | `AppInfo.swift` | 见 `02-数据模型设计.md` §1.1 |
| 1.6 | AppScanner 实现 | `AppScanner.swift` | 异步扫描 `/Applications`、`~/Applications`、`/System/Applications`，过滤后台应用 |
| 1.7 | IconCache 实现 | `IconCache.swift` | `NSCache<NSString, NSImage>` 包装，`NSWorkspace.icon(forFile:)` 懒加载 |
| 1.8 | AppIconView | `AppIconView.swift` | 显示图标 + 应用名，hover 放大 scale(1.05) |
| 1.9 | GridPageView 单页 | `GridPageView.swift` | `LazyVGrid`，单页固定5行，列数根据屏幕宽度自动计算 |
| 1.10 | LaunchpadView 根视图 | `LaunchpadView.swift` | 组装 GridPageView，背景暂用纯黑色占位 |
| 1.11 | 点击图标启动应用 | `LaunchpadViewModel.swift` | `NSWorkspace.shared.open(app.url)`，启动后隐藏窗口 |
| 1.12 | 测试验收 | — | 扫描结果完整，图标清晰，点击正常启动 |

#### Phase 1 验收标准
- [ ] 应用启动后，`allApps` 包含 `/Applications` 下所有可见 App
- [ ] 全屏窗口正确覆盖在所有普通窗口之上

| 2.2 | 多页翻页容器 | `LaunchpadView.swift` | 自定义水平偏移量方案（非 TabView），支持触控板双指滑动和方向键 |

| 2.4 | 背景虚化 | `BackgroundView.swift` | 读取壁纸文件 + `CIFilter.gaussianBlur()`，降级方案 `NSVisualEffectView` |

## 五、关键依赖关系

```
Phase 1（基础）
    └─ Phase 2（导航）← 依赖 Phase 1 的图标展示和 ViewModel 骨架
            └─ Phase 3（呼出）← 依赖 Phase 2 的显示/隐藏逻辑
                    └─ Phase 4（编辑）← 依赖 Phase 3 的完整呼出链路
                            └─ Phase 5（文件夹）← 依赖 Phase 4 的拖拽基础设施
                                    └─ Phase 6（系统集成）← 可并行开发部分
                                            └─ Phase 7（打磨）← 最后阶段
```

Phase 6 中的 `FSEventsWatcher` 可在 Phase 1 之后随时插入，不依赖 Phase 4/5。  
Phase 6 中的 `GestureMonitor` 依赖 Phase 3 的呼出逻辑。
