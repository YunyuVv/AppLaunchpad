## 一、整体架构分层

采用 **MVVM + 单向数据流** 架构，结合 SwiftUI 声明式 UI 和 AppKit 系统级能力。

```
┌──────────────────────────────────────────────────────────────┐
│                        App Entry Point                        │
│              AppDelegate / LaunchpadApp (@main)               │
└─────────────────────────┬────────────────────────────────────┘
                          │
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
┌──────────────┐  ┌──────────────┐  ┌──────────────────┐
│  Window 层   │  │  系统集成层   │  │   后台服务层      │
│ (NSPanel)    │  │ (AppKit)     │  │ (非UI)           │
│  全屏覆盖窗口 │  │ Dock图标     │  │ 应用扫描服务      │
│  背景截图层  │  │ 全局快捷键   │  │ FSEvents监听     │
│  SwiftUI Host│  │ 触控板手势   │  │ 图标缓存管理      │
└──────┬───────┘  └──────────────┘  └────────┬─────────┘
       │                                      │
       ▼                                      ▼
┌──────────────────────────────────────────────────────────────┐
│                       ViewModel 层                            │
│              LaunchpadViewModel (@Observable)                 │
│  状态：isVisible / currentPage / searchText / isEditMode      │
│  状态：apps / folders / layout / dragState                    │
└─────────────────────────┬────────────────────────────────────┘
                          │ @Bindable / @State
                          ▼
┌──────────────────────────────────────────────────────────────┐
│                        View 层 (SwiftUI)                      │
├──────────────┬───────────────┬──────────────┬────────────────┤
│ LaunchpadView│  SearchBarView│  GridPageView│  FolderView    │
│ (根容器)     │  (搜索框)     │  (单页网格)  │  (文件夹弹出)  │
├──────────────┴───────────────┴──────────────┴────────────────┤
│           AppIconView    PageIndicatorView                    │
│           (图标+名称)    (页码圆点)                           │
└──────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────────────────────────────────────────┐
│                       Model 层                                │
│  AppInfo / FolderInfo / LayoutData / UserPreferences         │
└──────────────────────────────────────────────────────────────┘
```

## 二、模块划分

### 2.1 核心模块清单

| 模块名 | 职责 | 类型 |
|-------|------|------|
| `AppDelegate` | App 生命周期、Dock 图标管理、激活策略切换 | AppKit |
| `LaunchpadWindowController` | 管理 NSPanel 全屏窗口的创建/显示/隐藏 | AppKit |
| `LaunchpadViewModel` | 全局状态管理，协调各子系统 | SwiftUI Observable |
| `AppScanner` | 异步扫描 /Applications 并过滤应用 | Service |
| `FSEventsWatcher` | 监听文件系统变化，触发重新扫描 | Service |
| `IconCache` | NSImage 图标内存缓存，支持懒加载 | Service |
| `LayoutStore` | 读写图标排列顺序和文件夹配置 | Persistence |
| `HotkeyManager` | 注册/注销全局快捷键 | Service |
| `GestureMonitor` | 监听全局触控板手势事件 | Service |
| `LaunchpadView` | 全屏根视图，组合所有子视图 | SwiftUI View |
| `GridPageView` | 单页图标网格 | SwiftUI View |
| `AppIconView` | 单个应用图标，支持抖动/拖拽/hover | SwiftUI View |
| `FolderView` | 文件夹收起/展开视图 | SwiftUI View |
| `SearchBarView` | 搜索输入框 | SwiftUI View |
| `PageIndicatorView` | 底部页码圆点 | SwiftUI View |

                    ┌───────────────┼────────────────┐

## 四、数据流设计

### 4.1 应用启动流程

```
App 启动
    │
    ├─ AppDelegate.applicationDidFinishLaunching
    │       ├─ 设置 LSUIElement（隐藏主窗口出现在 Dock 菜单栏，但显示启动台 Dock 图标）
    │       ├─ 注册全局快捷键 (HotkeyManager)
    │       ├─ 启动 FSEventsWatcher
    │       └─ 异步执行 AppScanner.scan()
    │
    └─ 后台扫描完成 → LaunchpadViewModel.apps 更新 → UI 就绪
```

### 4.2 呼出启动台流程

```
触发源（F4 / Dock点击 / 捏合手势）
    │
    ▼
LaunchpadViewModel.show()
    │
    ├─ 截取当前屏幕画面 → 生成虚化背景
    ├─ LaunchpadWindowController.show()
    │       └─ NSPanel makeKeyAndOrderFront()
    └─ 触发呼出动画（SwiftUI transition）
```

### 4.3 应用启动流程

```
用户点击图标
    │
    ▼
AppIconView.onTapGesture
    │
    ▼
LaunchpadViewModel.launch(app: AppInfo)
    │
    ├─ 触发关闭动画
    ├─ NSWorkspace.shared.open(app.url)
    └─ LaunchpadWindowController.hide()
```

### 4.4 状态管理单向数据流

```
用户操作 (手势/键盘/点击)
        │
        ▼ Action
LaunchpadViewModel (单一数据源)
        │
        ▼ State 变更
SwiftUI View 重新渲染
```

## 五、窗口管理设计

### 5.1 NSPanel 配置

```swift
// 窗口关键配置
panel.level = .screenSaver          // 覆盖所有普通窗口
panel.collectionBehavior = [
    .canJoinAllSpaces,              // 在所有 Space 显示
    .fullScreenAuxiliary            // 全屏模式下也显示
]
panel.isOpaque = false              // 透明窗口
panel.backgroundColor = .clear
panel.styleMask = .borderless       // 无边框
panel.frame = NSScreen.main!.frame  // 铺满全屏
```

### 5.2 激活策略切换

```
正常状态（后台）:
    NSApp.activationPolicy = .accessory
    → App 不出现在 Cmd+Tab 列表，不占用 Dock 空间（只有启动台图标）

启动台显示时:
    NSApp.activationPolicy = .regular（短暂激活以接收键盘事件）
    → 接收键盘输入（搜索/Escape/方向键）

启动台关闭时:
    → 恢复 .accessory
```

## 六、SwiftUI 与 AppKit 桥接策略

| 需求 | 方案 |
|-----|------|
| 全屏窗口 | `NSPanel` 由 AppKit 管理，内容用 `NSHostingView<LaunchpadView>` 承载 |
| 背景虚化 | AppKit 截图 + Core Image 模糊，结果作为 SwiftUI `Image` 传入 |
| 全局快捷键 | AppKit `NSEvent.addGlobalMonitorForEvents` |
| 触控板捏合 | AppKit `NSEvent` magnification 事件 |
| Dock 图标点击 | `AppDelegate.applicationShouldHandleReopen` |
| 拖拽排序 | SwiftUI `onDrag` / `onDrop` + 自定义 DragDelegate |
| 文字输入（搜索） | SwiftUI `TextField` with `focused()` |

## 七、并发模型

| 场景 | 执行线程 | 方案 |
|-----|---------|------|
| 应用扫描 | 后台线程 | `Task { await AppScanner.scan() }` |
| 图标加载 | 后台线程（按需） | `async let icon = IconCache.icon(for: app)` |
| FSEvents 回调 | 后台线程 | `Task.detached` + debounce → 主线程更新 |
| UI 状态更新 | 主线程 | `@MainActor` + `@Observable` |
| 屏幕截图 | 主线程（需要） | `CGWindowListCreateImage` 在主线程执行 |

## 八、关键设计决策

### 8.1 为什么选 MVVM 而非 TCA

- 项目规模中等，TCA 引入的复杂度不值得
- SwiftUI `@Observable` 已足够管理状态
- 减少外部依赖，降低维护成本

### 8.2 为什么不使用沙盒

- 沙盒限制无法访问 `/Applications` 完整路径
- 无法使用 `FSEvents` 监听系统目录
- 无法注册全局快捷键（Sandbox 下需 Accessibility 权限且有限制）
- 结论：使用 **Hardened Runtime（非沙盒）** + 必要 entitlements

### 8.3 布局计算策略

- 图标网格用 `LazyVGrid` 实现，不使用 `List`
- 翻页用 `TabView`（`.page` 样式）或自定义 `GeometryReader` + 偏移量
- 推荐自定义偏移量方案，可精确控制动画和手势判定阈值

### 8.4 图标懒加载策略

- 首次呼出：只加载当前页（第1页）图标
- 翻页前预加载下一页图标
- 非可见页图标保留内存缓存（NSCache 自动淘汰）
