# 分发与签名分析

**版本**: v1.0.0  
**日期**: 2026-07-20

> **核心问题**：如果不签名，这个 App 能否在其他 macOS 设备上运行？

---

## 一、macOS 代码签名机制概述

macOS 通过 **Gatekeeper** 机制保护用户不运行恶意软件。Gatekeeper 在用户首次运行 App 时检查：

| 检查项 | 未签名 | 仅开发者签名 | 开发者签名+公证 |
|-------|-------|------------|---------------|
| Gatekeeper 放行 | ❌ 默认拒绝 | ⚠️ 需手动允许 | ✅ 自动放行 |
| 用户操作成本 | 需在系统设置中手动允许 | 右键→打开，确认一次 | 直接双击运行 |
| 网络下载后可用 | ❌（有隔离属性） | ⚠️ 需用户确认 | ✅ |
| 适合分发 | 不推荐 | 小范围可行 | 推荐 |

---

## 二、不签名的情况分析

### 2.1 完全不签名（ad-hoc 以外）

**运行限制**：
- macOS 会显示「无法打开，因为无法验证开发者」
- 用户必须前往 **系统设置 → 隐私与安全性 → 仍要打开** 手动授权
- 每台设备首次运行都需要此步骤

**本项目的额外影响**：
- 本项目需要 **Accessibility 权限**（触控板手势），该权限与签名绑定——未签名应用的 Bundle ID 无法稳定标识，权限可能在 App 重装后失效
- 无法监听全局事件（`NSEvent.addGlobalMonitorForEvents`）在部分 macOS 版本上未签名时会被沙盒策略限制

### 2.2 ad-hoc 签名（自签名，无开发者账号）

```bash
codesign --force --deep --sign - /path/to/AppLaunchpad.app
```

**效果**：
- App 本身可以在**开发机**上运行
- 分发到其他机器：同样需要用户手动在系统设置中允许
- 相比完全不签名：Accessibility 权限绑定更稳定（有 Team ID hash）

### 2.3 结论：不签名能否在其他设备使用？

| 场景 | 结论 |
|-----|------|
| 自用（开发机） | ✅ 可以，关闭 Gatekeeper 或手动允许即可 |
| 给少数技术用户使用 | ⚠️ 可以，但需要指导用户手动操作（右键打开 or 系统设置允许） |
| 公开分发给普通用户 | ❌ 不推荐，用户体验差，多数普通用户不知道如何绕过 |
| 企业内部分发（MDM） | ✅ 可以，MDM 可强制信任特定 App |

## 三、签名方案对比

### 方案一：不签名（仅供自用/内部）

**适用场景**：只在自己的 Mac 上使用，或通过 MDM 分发到公司内部设备

**操作步骤（接收方）**：
```
方法A：右键点击 App → 打开 → 在弹出框中选择「打开」
方法B：系统设置 → 隐私与安全性 → 找到被阻止的 App → 点击「仍要打开」
方法C（临时关闭 Gatekeeper，谨慎使用）：
    sudo spctl --master-disable
```

**优点**：无需 Apple 开发者账号（$99/年），开发最简单  
**缺点**：用户体验差，功能限制（Accessibility 权限不稳定）

---

### 方案二：开发者签名（推荐，无公证）

**前提**：申请 Apple Developer Program 账号（$99/年）

**签名流程**：
```bash
# 1. 在 Xcode 中配置 Team 和 Bundle ID
# 2. 导出 .app
# 3. 签名
codesign --force --deep --sign "Developer ID Application: Your Name (XXXXXXXX)" \
    --entitlements AppLaunchpad.entitlements \
    AppLaunchpad.app

# 4. 打包为 .dmg 分发
```

**效果**：
- 用户首次运行：右键→打开，确认一次即可
- Accessibility 权限稳定绑定到 Team ID
- 无需额外操作（仅首次确认）

---

### 方案三：开发者签名 + 公证（最佳分发体验）

**前提**：Apple Developer Program 账号

**公证流程**：
```bash
# 1. 签名（同方案二）

# 2. 提交公证（约需 2-5 分钟）
xcrun notarytool submit AppLaunchpad.dmg \
    --apple-id "your@apple.com" \
    --team-id "XXXXXXXX" \
    --password "app-specific-password" \
    --wait

# 3. 附加公证票据到 App
xcrun stapler staple AppLaunchpad.app
```

**效果**：
- 用户双击直接运行，无任何提示
- 苹果服务器验证 App 无恶意代码
- 可通过 GitHub Releases / 官网 / DMG 正常分发

---

### 方案四：Mac App Store 分发

**前提**：Apple Developer Program + 沙盒合规

**本项目是否适合 MAS 分发**：❌ **不适合**

原因：
1. MAS 应用必须启用沙盒（`com.apple.security.app-sandbox = true`）
2. 沙盒限制无法访问 `/Applications` 完整路径（只能通过用户授权的 Open Panel 访问）
3. 沙盒限制无法注册全局快捷键（`NSEvent.addGlobalMonitorForEvents`）
4. 无法监听 FSEvents 系统目录

**结论**：本项目必须以 **非沙盒模式** 分发，MAS 不可行。

## 四、推荐分发方案

### 4.1 个人/开发自用

```
开发者模式构建 → ad-hoc 签名 → 直接运行
（首次需在系统设置允许一次）
```

### 4.2 公开分发

```
Apple Developer 账号
    → Xcode Archive → Developer ID 签名
    → 公证 (notarytool)
    → 附加票据 (stapler)
    → 打包 .dmg
    → GitHub Releases / 官网下载
```

### 4.3 企业/团队内部

```
选项A：MDM（如 Jamf）→ 推送安装，无需签名授权
选项B：内部 PKG 安装包 → 配合公司证书
```

## 五、所需 Entitlements 配置

```xml
<!-- AppLaunchpad.entitlements -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
    "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <!-- 不启用沙盒（必须，原因见上文） -->
    <key>com.apple.security.app-sandbox</key>
    <false/>
    
    <!-- Hardened Runtime: 允许执行 Apple 脚本 -->
    <key>com.apple.security.automation.apple-events</key>
    <true/>
    
    <!-- 读取用户文件（访问 ~/Applications） -->
    <key>com.apple.security.files.user-selected.read-only</key>
    <true/>
    
    <!-- 注意：NSWorkspace.open() 无需特殊 entitlement -->
    <!-- 注意：FSEvents 对系统路径无需特殊 entitlement（非沙盒） -->
    <!-- 注意：全局快捷键 + Accessibility 通过系统隐私设置授权，非 entitlement -->
</dict>
</plist>
```

## 六、分发决策树

```
是否有 Apple Developer 账号？
    │
    ├─ 否
    │   └─ 只能自用或技术用户使用
    │       └─ ad-hoc 签名 → 接收方手动在系统设置允许
    │
    └─ 是
        │
        ├─ 小范围分发（技术用户）
        │   └─ Developer ID 签名（无公证）→ 右键打开一次
        │
        └─ 公开分发（普通用户）
            └─ Developer ID 签名 + 公证 → 双击直接运行 ✅
```

## 七、开发阶段建议

| 阶段 | 签名方式 | 说明 |
|-----|---------|------|
| 开发期 | Debug 构建，自动 ad-hoc | Xcode 直接运行，无需额外处理 |
| 内测期 | Developer ID 签名（无公证） | 分发给测试人员，告知右键打开 |
| 发布期 | Developer ID 签名 + 公证 | 正式用户零门槛运行 |
