# 文件夹面板打开时背景是否虚化 —— 方案分析

> 状态：**已落地（方案 C：跟随背景样式自适应虚化）**，2026-07-25
> 关联代码：`AppLaunchpad/Views/FolderExpandedView.swift`、`AppLaunchpad/Views/BackgroundView.swift`、`AppLaunchpad/Models/UserPreferences.swift`

---

## 1. 现状

文件夹面板（`FolderExpandedView`）以 `ZStack` 叠加在全屏启动台之上（`LaunchpadView` 中 `zIndex(1000)`），其底层背景目前是：

```swift
// FolderExpandedView.swift:84-87
ZStack {
    Color.black.opacity(0.45)          // ← 仅一层纯黑压暗，无模糊
        .ignoresSafeArea()
        .onTapGesture { onDismiss() }
    ...
}
```

也就是说：**面板打开时，背后的主网格只被 45% 黑遮罩压暗，图标和文字仍然清晰锐利，没有被虚化（失焦）。**

补充背景：整个启动台自己的全屏背景（`BackgroundView`）已经做了模糊——
- 磨砂模式：`NSVisualEffectView(material: .fullScreenUI, blendingMode: .behindWindow)` 模糊**桌面**；
- 玻璃模式：`NSGlassEffectView` 折射**桌面**。

注意一个关键技术区别：**`.behindWindow` 模糊的是窗口「后方」的桌面；而文件夹背后想虚化的是窗口「内部」的主网格，需要用 `.withinWindow` 混合模式的毛玻璃（这是 macOS 菜单/弹窗/通知中心虚化自身内容的标准做法）。** 两者不能混用。

---

## 2. 诉求

文件夹打开时，用户希望背后的主网格「虚化一下」（失焦/模糊），形成更明确的**前后层次**：文件夹在前、背景退后，注意力更聚焦，视觉噪音更低。

---

## 3. 方案对比

### 方案 A — 保持现状：仅压暗，不虚化
维持 `Color.black.opacity(0.45)`。

- ✅ 零改动、零风险，与原生 Launchpad 文件夹「以压暗为主、弱模糊」的观感一致。
- ❌ 背景主网格仍清晰，文件夹打开时层次感弱；图标+文字在 45% 黑下仍可辨，可能分散注意力。

### 方案 B — 统一轻虚化（withinWindow 毛玻璃 + 轻压暗）⭐ 推荐首选
用 `NSVisualEffectView(blendingMode: .withinWindow, material: .popover / .fullScreenUI)` 替换 `Color.black`，其上再叠一层**更轻**的黑遮罩（约 `0.2~0.3`，比 0.45 低，因为虚化本身已降噪）。两种背景样式共用同一套实现。

- ✅ 聚焦强、层次好，最贴近 macOS 系统弹窗（菜单/控制中心/通知中心）习惯，视觉更高级。
- ✅ 实现简单：新增一个 `NSViewRepresentable` 包裹 `withinWindow` 毛玻璃即可。
- ❌ 磨砂模式下主网格本就叠在模糊桌面上 → 二次模糊会偏柔（通常可接受，必要时略加压暗补偿可读性）。
- ❌ 玻璃模式下，withinWindow 毛玻璃与全屏液态玻璃的质感可能「略不搭」。

### 方案 C — 跟随背景样式自适应虚化（最一致，略复杂）
让文件夹背后的虚化**复用与全屏背景相同的技术**，风格 100% 统一：

- 磨砂模式：backdrop = `.withinWindow` + `.fullScreenUI` 毛玻璃 + 轻黑遮罩；
- 玻璃模式：backdrop = 全屏 `NSGlassEffectView`（withinWindow）+ 轻黑遮罩，文件夹背后呈现液态玻璃折射。

- ✅ 与用户已选背景风格完全统一；玻璃模式下文件夹背后是液态玻璃质感，非常「macOS 26」。
- ❌ 两套实现、复杂度最高；玻璃模式「双层玻璃」需真机验证观感，可能过载。

---

## 4. 推荐结论

| 维度 | A 现状 | B 轻虚化（推荐） | C 自适应虚化 |
|---|---|---|---|
| 聚焦/层次 | 弱 | 强 | 强 |
| 与原生一致 | 是 | 接近 | 接近 |
| 与玻璃风格统一 | — | 一般 | 最好 |
| 实现复杂度 | 无 | 低 | 中高 |
| 风险 | 无 | 低 | 中（双层玻璃待验） |

- **是否「需要」**：不是原生强制项，属**体验升级**。对齐原生则可不做（A）；追求现代模态聚焦舒适度则**建议做**（B/C）。
- **用户舒服度**：轻虚化（material 自带适度模糊）+ 轻压暗，比纯压暗更聚焦、更安静；但虚化半径**不宜过大**，否则背景糊成一团也难受。
- **首选**：**方案 B**——实现简单、舒适度高、风险低。若你常用「液态玻璃」背景且追求极致统一，再升级到 **方案 C**。

---

## 5. 实现要点（确认后落地）

1. 新增 `FolderBackdropView: NSViewRepresentable`，包 `NSVisualEffectView`：
   - `blendingMode = .withinWindow`（模糊窗口内主网格，非桌面）；
   - `material`：磨砂/统一模式用 `.popover` 或 `.fullScreenUI`，玻璃模式按方案 C 改用 `NSGlassEffectView`；
   - `state = .active`。
2. 在 `FolderExpandedView` 中，用 `FolderBackdropView` + 轻黑遮罩（如 `Color.black.opacity(0.25)`）替换 `Color.black.opacity(0.45)`，保留 `.onTapGesture { onDismiss() }`（点击空白处关闭，手势放最底层）。
3. `withinWindow` 毛玻璃会**同时**模糊全屏 `BackgroundView`（其本身已是模糊）→ 磨砂模式二次模糊偏柔，可把遮罩压暗到 `0.3` 左右补偿可读性，具体按真机观感微调。
4. 玻璃模式若采用 C：需验证 `NSGlassEffectView` 在 `withinWindow` 下是否可用（当前全屏玻璃是 `.behindWindow` 采样桌面，withinWindow 玻璃待实测）。

---

## 6. 是否做成设置项

可选增强：在「外观」设置里加一个开关 **「文件夹面板背景虚化」**（默认开），甚至配虚化强度/压暗度。
- 优点：给用户选择权，避免有人觉得虚化过头。
- 代价：设置面板多一项；建议**先按默认值落地 B**，开关作为后续增强，不阻塞本次。

---

## 7. 风险清单

- 磨砂模式二次模糊偏柔，需微调遮罩透明度。
- 玻璃模式双层玻璃观感待真机验证（仅方案 C 涉及）。
- 性能：`withinWindow` 为硬件加速，影响可忽略。
- 手势：backdrop 仅视觉层，点击关闭手势已放在最底层，不受影响。

## 8. 实施记录（方案 C 已落地，2026-07-25）

用户确认选 **C**。改动点（仅 `FolderExpandedView.swift`，未新增文件、无需 `xcodegen generate`）：

1. 背景层由原来的 `Color.black.opacity(0.45)` 纯黑压暗，替换为 `FolderBackdropView` + 轻压暗层：
   ```swift
   FolderBackdropView(isGlass: prefs.backgroundStyle == 1)
       .ignoresSafeArea()
       .onTapGesture { onDismiss() }
   Color.black.opacity(prefs.backgroundStyle == 1 ? 0.2 : 0.3)
       .ignoresSafeArea()
       .allowsHitTesting(false)
   ```
   - 点击空白关闭手势挂在最底层 `FolderBackdropView` 上，dim 层 `allowsHitTesting(false)` 放行命中。
   - 压暗度：玻璃模式 `0.2`（保留折射感）、磨砂模式 `0.3`（补偿二次模糊偏柔）。

2. 新增 `FolderBackdropView: NSViewRepresentable`，按 `backgroundStyle` 二选一：
   - 玻璃（`isGlass=true`）：`NSGlassEffectView`（cornerRadius=0, tintColor=nil, style=.regular）——与全屏 `GlassBlurView` 完全同构。
   - 磨砂（`isGlass=false`）：`NSVisualEffectView(material: .fullScreenUI, blendingMode: .withinWindow, state: .active)`——**关键**用 `.withinWindow`（模糊窗口内主网格），而非全屏背景的 `.behindWindow`（模糊桌面）。

导致所有 `@Observable` 文件（UserPreferences/GesturePane/GlassHostingView/GridGeometry 等）无法编译，
