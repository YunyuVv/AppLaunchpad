# 翻页功能 — 优化方案

## 一、当前翻页系统全景

项目有三条独立的翻页路径：

| 路径 | 文件 | 触发条件 | 机制 |
|------|------|---------|------|
| 拖拽边缘翻页 | `DragController.detectEdgeScroll` | 拖拽中光标进入屏幕左右 100px 区域 | Timer 0.8s → 翻一页即停 |
| 手势翻页 | `LaunchpadView.pagingDragGesture` | 非编辑模式，起点在网格空白/间隙，水平拖拽 | `minimumDistance: 30`，translation > 50px 松手翻页，`spring(0.38,0.18)` |
| 键盘翻页 | `NavigationController.moveGridSelection` | 方向键走到底越界 | 即时切换 pageIndex + 选中位 |

**注意**：macOS 原生 Launchpad 拖拽到边缘也只翻一页就停、不会连续翻，所以不引入连续翻页。

---

## 二、存在的问题与优化方向

### P0 — 必须修（影响正常使用 / 体验差距明显）

| # | 问题 | 现状 | 目标 |
|---|------|------|------|
| ① | 屏幕宽度硬编码，多屏时边缘检测失效 | `NSScreen.screens.first?.frame.width`（物理连接顺序，不是活跃屏幕） | 改用 `NSScreen.main?.frame.width`（key window 所在屏幕） |
| ② | 边缘翻页延迟 0.8s，用户体感「卡了」 | `Timer(timeInterval: 0.8, …)` | 改为 0.5s（接近原生体感） | ✅ 已实现 |
| ③ | 翻页无 slide 过渡动画，页面内容瞬间切换 | `pagingView` 只改 `currentPageIndex`，无过渡效果 | 方向性滑入 + 淡入（`pageTransitionOffset` + `pageTransitionOpacity`） | ✅ 已实现 |

### P1 — 建议做（让翻页更自然、更有品质感）

| # | 问题 | 方案 |
|---|------|------|
| ④ | 停在边缘 0.5s 期间无视觉反馈，用户不确定系统是否感知到 | `DragState` 加 `edgeScrollDirection`，`LaunchpadView` 根层级 overlay 半透明箭头渐亮 |
| ⑤ | 手势翻页 threshold 偏大（50px），13 寸屏幕上需滑半程触控板 | 改为 30px，与 `minimumDistance` 一致 |

### 3.3 翻页过渡动画（P0-③）✅ 已实现（方案A：空白拖拽邻居预览 + 连续滑入）

**文件**：`LaunchpadView.swift`（`pagingView` + `pagingDragGesture.onEnded` + `onChange`）

**目标**：翻页跟手、相邻页可见、松手无“先弹回再滑入”的两段式跳变，且**完全不碰拖拽弹簧让位（make-way）**。

**三条翻页路径，互不干扰**：

1. **空白拖拽翻页（跟手、无空窗）**：`pagingDragGesture` 在网格空白/间隙起手（`anyItemAtIconPoint` 为 false），拖拽中 `pagingView` 渲染“当前页 + 相邻页”并排（`ZStack`，相邻页纯展示：空回调 + `dragState: DragState()`），整体随 `dragOffsetX` 平移 → 拖的过程中相邻页始终可见，**无空窗**。
2. **松手连续滑入（去两段式跳变）**：`onEnded` 越过阈值（50px）后，把新页入场起点 `pendingFlipStart` 设为“相邻页当时的位置”（`dragOffsetX ± 页宽`），再 `goToPage(target)`；`onChange` 用该起点 spring 归零，新页从手指位置连续滑入，**无先弹回、无空窗残留**；未越阈值则当前页从拖拽位置弹簧回正中。
3. **外部翻页统一为整页滑动**（点页面指示器 / 方向键 / 触控板横扫 / 鼠标滚轮）：走 `onChange`，`pendingFlipStart == nil` → 新页从「±整页宽」位置滑入 + **无淡入**，与鼠标拖拽同视觉语言（2026-07-24 统一）。

```swift
// @State（LaunchpadView 顶部）
@State private var pageTransitionOffset: CGFloat = 0
@State private var pageTransitionOpacity: Double = 1.0
@State private var pendingFlipStart: CGFloat? = nil   // 拖拽触发翻页时=相邻页位置；外部翻页=nil

// pagingView：拖拽中渲染当前页+相邻页；否则单页走 pageTransitionOffset/Opacity
if isDragging, dragOffsetX != 0 {
    ZStack(alignment: .topLeading) {
        currentPage.offset(x: dragOffsetX)
        if hasNext, dragOffsetX < 0 { nextPage.offset(x: dragOffsetX + W) }
        if hasPrev, dragOffsetX > 0 { prevPage.offset(x: dragOffsetX - W) }
    }
} else {
    currentPage.offset(x: pageTransitionOffset).opacity(pageTransitionOpacity)
}

// onEnded 越过阈值：新页从相邻页位置连续滑入
let W = viewModel.gridGeometry?.size.width ?? 0
pendingFlipStart = goingNext ? (startX + W) : (startX - W)
viewModel.goToPage(target)

// onChange：所有路径统一为「整页宽方向性滑动、无淡入」
// 拖拽触发：起点=相邻页当时位置(pendingFlipStart)；外部：起点=±整页宽
let W = viewModel.gridGeometry?.size.width ?? 0
let start = pendingFlipStart ?? (viewModel.pageFlipGoingForward ? W : -W)
pendingFlipStart = nil
pageTransitionOffset = start
pageTransitionOpacity = 1.0
withAnimation(.spring(duration: 0.4, bounce: 0.15)) { pageTransitionOffset = 0; pageTransitionOpacity = 1.0 }
```

**关键约束（红线）**：
- `gridGeometry` 仍由当前页 `GeometryReader` 每帧写入（用 `let _ = { viewModel.gridGeometry = … }()` 触发副作用，规避 @ViewBuilder 裸赋值）；翻页偏移与 `gridGeometry` 完全解耦，**make-way 落点不受影响**。
- 相邻页为只读预览，绝不参与 make-way / 落点计算（其 `pageItemsWithDrag` 返回基础布局）。
- **不采用“所有页并排宽容器 + 整体平移”（早期失败的 LaunchNext 式）**：会把所有页塞进被平移的宽容器，导致 `gridGeometry.origin` 偏移、非首页 make-way 落点错乱，本次已踩坑回滚。
- 不引入 `.id(currentPageIndex)`：会重建视图、中断拖拽手势（“拖到第二页卡死”）。
- 页宽 `W` 必须从实时 `gridGeometry.size.width` 读取，禁止在 `.onAppear` 捕获（入场 `.scaleEffect` 弹入动画会让一次性捕获的宽度缩水 8%，导致翻页与落点整体偏移）。
- **翻页去掉淡入（opacity 恒 1.0）会暴露图标缓存漏命中 → 灰框闪现（2026-07-24 踩坑）**：灰框是 `AppIconView.iconImage` 中 `icon == nil` 时的 `RoundedRectangle` 占位。翻页时目标页 `AppIconView` 为**新建实例**，构造时同步取 `IconCache.cachedIcon(for:)`；若某 app 图标尚未预热进缓存则返 `nil` → 灰框，等 `.task` 异步加载完才替换。**早期外部翻页的 `opacity 0→1` 淡入把灰框半透明遮挡住了、几乎看不见**；改成「整页滑动、无淡入」后灰框实打实露出，易误判为缓存 bug，但**缓存逻辑本身没被改坏**，只是遮挡它的"幕布"被撤了。修法（切勿加回淡入掩盖）：`IconCache.cachedIcon` 缓存未命中时同步取一次系统图标并回填缓存（`NSWorkspace.shared.icon(forFile:)`），保证视图重建时永远有图标。红线：**任何"去掉/缩短翻页淡入"的改动，必须先确认 `IconCache.cachedIcon` 已做到「未命中即同步兜底」**，否则灰框必重现。

### 3.4 边缘视觉反馈（P1-④）

**效果**：光标停在边缘时，对应方向出现**半透明箭头**，0.5s 内从 `opacity 0.3` 渐亮到 `0.6`，翻页后消失。

**3.4.1 DragState 加状态**

```swift
// DragState.swift 加字段：
/// 边缘翻页等待方向（nil = 不在边缘）
var edgeScrollDirection: EdgeScrollSide? = nil

enum EdgeScrollSide {
    case left, right
}
```

**3.4.2 DragController.detectEdgeScroll 写状态**

```swift
// 进入边缘时设 direction，退出时清 nil（stopEdgeScrollTimer 时一并清）
if location.x < edgeZone { data.dragState.edgeScrollDirection = .left }
else if location.x > screenWidth - edgeZone { data.dragState.edgeScrollDirection = .right }
else { data.dragState.edgeScrollDirection = nil }

// Timer fire 后（翻页完成）立即清：
data.dragState.edgeScrollDirection = nil

// stopEdgeScrollTimer 也清：
data.dragState.edgeScrollDirection = nil
```

**3.4.3 LaunchpadView 显示指示器**

在根 `ZStack` 最上层 overlay（仅 `dragState.edgeScrollDirection != nil` 时显示）：

```swift
if let dir = viewModel.dragState.edgeScrollDirection {
    Image(systemName: dir == .left ? "chevron.left" : "chevron.right")
        .font(.system(size: 48, weight: .light))
        .foregroundColor(.white.opacity(0.5))
        .position(x: dir == .left ? 60 : screenFrame.width - 60,
                  y: screenFrame.height / 2)
        .transition(.opacity)
        .animation(.easeIn(duration: 0.5), value: viewModel.dragState.edgeScrollDirection)
}
```

### 3.6 触控板双指横扫跟手（2026-07-24 实施）

**目标**：触控板翻页与鼠标拖拽、原生 Launchpad 一致——双指横扫时内容**实时跟随手指平移**，松手按阈值吸附翻页（连续滑入），而非松手才"跳一整页"。

**跨层桥接（AppKit ↔ SwiftUI）**：触控板事件来自 `LaunchpadWindowController.scrollMonitor`（AppKit 层），而实时偏移状态原本在 `LaunchpadView` 的 `@State`（SwiftUI 层），AppKit 层访问不到。故把跟手状态提升为共享状态：
- `LaunchpadData` 新增 `trackpadPagingOffsetX: CGFloat`（实时偏移，语义同 `dragOffsetX`：负=看下一页）与 `trackpadPagingCommit: TrackpadPageFlip?`（松手一次性翻页意图，struct 包装 offset+target，规避元组 Equatable 兼容问题）。
- `LaunchpadViewModel` 转发这两个属性。

**触控板分支（`.changed` 实时跟手 / `.ended` 吸附）**：
```swift
// .changed：累积 scrollingDeltaX，×gain 放大后映射为跟手偏移并 clamp 到 ±W
// 左滑(自然滚动 scrollingDeltaX<0 → accumulatedScrollX<0) → off<0 → 看下一页（与鼠标拖拽 dragOffsetX<0 同义）
let gain: CGFloat = 2.0
let off = max(-pageW, min(pageW, accumulatedScrollX * gain))
viewModel.trackpadPagingOffsetX = off
// .ended：水平主导且增益后位移 > W*0.10 则翻页，否则弹簧回弹
// 方向与 .changed 一致：gained virtualX<0(左滑) = 下一页
let virtualX = accumulatedScrollX * gain
let goingNext = virtualX < 0
if abs(virtualX) > pageW * 0.10, target != current {
    viewModel.trackpadPagingCommit = TrackpadPageFlip(offset: max(-pageW, min(pageW, virtualX)), target: target)
    viewModel.trackpadPagingOffsetX = 0
} else {
    withAnimation(.spring(duration: 0.4, bounce: 0.15)) { viewModel.trackpadPagingOffsetX = 0 }
}
```
方向（已修正 2026-07-24）：早期版本 `.changed` 误写成 `off = -accumulatedScrollX`、`.ended` 又写 `goingNext = accumulatedScrollX > 0`——两者符号不一致，导致左滑时「视觉显示上一页、却翻到下一页」，**方向彻底反掉**。正确实现：偏移**不取反**（`off = accumulatedScrollX * gain`），且 `.ended` 的 `goingNext` 必须与之同号（`virtualX < 0` = 左滑 = 下一页）。双指左滑→下一页、右滑→上一页，与原生 Launchpad 一致。

灵敏度（已修正 2026-07-24）：原阈值 `W*0.15`（约 216 点）对触控板累积量偏高、且 1:1 映射让页面跟手幅度小，翻页困难。修正：偏移 ×gain 放大跟手幅度，阈值降为 `W*0.10`（对原始累积量仅约 `W*0.05` ≈ 70 点即可触发），小幅度横扫也能顺畅翻页。

**增益可配置（2026-07-24）**：写死的 `gain` 改为读取 `UserPreferences.trackpadPagingGain`（默认 4.0，范围 1.0~8.0，didSet 写 UserDefaults 并 clamp）；`LaunchpadWindowController` 两个分支（`.changed`/`.ended`）均从单例读取。`WindowController` 不持有绑定，靠单例即时读取——设置滑块拖动即生效，无需重启。设置面板新增「手势」分类（`SettingsSection.gesture` + `GesturePane.swift`），含「跟手灵敏度」滑块（1...8，step 0.5）。`gain` 越大=手指少滑一点就跟满整页、越省力；1x=1:1 跟手。翻页方向（左滑下一页）与灵敏度相互独立。

**渲染合并**：`LaunchpadView.pagingView` 的跟手分支条件从 `isDragging && dragOffsetX != 0` 扩展为 `(isDragging && dragOffsetX != 0) || (trackpadPagingOffsetX != 0)`；ZStack 偏移统一用 `off = isDragging ? dragOffsetX : trackpadPagingOffsetX`。`trackpadPagingOffsetX` 归 0 即自动切回单页（回弹动画在 ZStack 跟手渲染内完成，无需额外 bool 状态）。

**松手提交（防闪现）**：`LaunchpadView` 新增 `onChange(of: trackpadPagingCommit)`，消费时**先同步设 `pendingFlipStart` + `pageTransitionOffset` 再 `goToPage`**，复用鼠标拖拽的连续滑入逻辑——与 3.3 红线「goToPage 前同步设起点」同源，避免 `onChange(currentPageIndex)` 异步前用旧偏移(0)渲染新页闪现正中。

**关键约束（红线）**：
- 触控板跟手**复用现有"当前页 + 相邻页"ZStack 框架**，绝不搬回"所有页并排宽容器整体平移"（会让 `gridGeometry.origin` 偏移破坏 make-way 落点，见 3.3 红线）。
- `.changed` 高频写 `trackpadPagingOffsetX`（@Observable 属性）会触发 SwiftUI 重渲染，频率与鼠标拖拽 `@State` 更新相当，可接受；`gridGeometry` 仍由当前页 `GeometryReader` 每帧写入、与翻页偏移解耦，make-way 落点不受影响。
- 翻页去淡入（3.3 统一）后灰框暴露问题已由 `IconCache.cachedIcon` 同步兜底根治（见 3.3 红线"翻页去掉淡入会暴露灰框"），触控板跟手不引入新灰框风险。
- 惯性滚动阶段（`event.momentumPhase` 非空）被 `scrollMonitor` 的 guard 排除，不驱动跟手——仅处理用户手指阶段，简化实现（如需惯性跟手可后续扩展）。
