# 文件夹管理功能

> 日期：2026-07-24 | 当前已实现的功能说明

---

## 一、创建文件夹

### 交互方式

拖拽 app A 到 app B 的图标上方 → B 放大至 1.15 倍 → 松手 → 在 B 的位置创建文件夹（包含 A 和 B）。

### 检测规则

| 光标位置 | 行为 |
|----------|------|
| 在 cell 中心 70% 区域 | 触发文件夹创建意图 → 目标 app 停止让位 + 放大 |
| 在 cell 左右各 15% 边际 | 不触发 → 正常 make-way 弹簧让位（用于重排） |
| 翻页到其他页面 | 暂不支持跨页创建文件夹，走重排逻辑 |

### 底层流程

```
detectHoverTarget → hoverTargetBundleID / hoverTargetSlot 写入 DragState
    ↓
pageItemsWithDrag 检测 hoverTargetSlot → 走 hover 模式（仅 remove 被拖 app，不 insert）
    ↓ 网格留空
GridPageView 渲染 → 目标 app scaleEffect(1.15) + 浮动图标悬停
    ↓ 用户松手
endDrag 分支 1 → removeFromPage(A) → findInPage(B) → removeFromPage(B)
    ↓
FolderController.createFolder → LayoutData.folders 写入
    ↓
LayoutStore.save → 持久化到 layout.json
```

## 二、添加到已有文件夹

### 交互方式

拖拽 app 到已有文件夹图标上方 → 文件夹放大 → 松手 → app 添加到文件夹内部。

### 底层流程

```
detectHoverTarget → hoverTargetFolderID 写入 DragState
    ↓ 松手
endDrag 分支 2 → removeFromPage(app) → FolderController.addApp
```

## 三、文件夹缩略图 (FolderThumbnailView)

### 显示规则

- **固定 3×3** 网格布局（9 格），不根据 app 数量动态调整——2 个 app 也占满 3×3
- 从左到右、从上到下填充，多余格子留白
- app 数量 = 0 → 文件夹自动删除
- 外边距 6pt，格间距 2pt，圆角背景 + 半透明边框

### 图标加载

- `.task(id: folder.appIDs)` 异步加载图标——文件夹内容变化时自动重载，避免添加 app 后新图标一直转圈
- 最大缓存 9 个图标（3×3 上限）

### 编辑模式

- 长按文件夹进入编辑模式，显示删除按钮（×）
- 点击删除 → `FolderController.deleteFolder` → 文件夹解散，内部 app 展开回主网格

## 四、文件夹内容面板 (FolderExpandedView)

### 显示效果

- 点击文件夹 → 全屏半透明遮罩 + 居中面板（占屏幕 70% 宽高）
- 面板结构：顶部文件夹名（居中，无关闭按钮）+ 5 列图标网格 + 超出时 ScrollView 滚动
- 图标尺寸使用传入的 `iconSize`（来自设置面板），不自行计算
- 每行图标**左对齐**（末尾 Spacer 推重）
- 图标组件复用 `AppIconView`，与主网格完全一致
- 点击遮罩 → 关闭；点击 app → 启动并关闭
- 无右上角 × 关闭按钮（点遮罩即可）

### 内部拖拽排序

- 面板内自管一套 make-way 弹簧让位（`.spring(response: 0.3, dampingFraction: 0.9)`）
- 被拖 app 在原位 opacity=0 留空，浮动图标（scaleEffect 1.12）跟随光标
- 落点通过 cellFrames（`CellFrameKey` PreferenceKey）hit-test 确定目标槽位
- 松手时通过 `onReorder` 回调写回 `FolderInfo.appIDs` 并持久化
- **不支持**在面板内创建子文件夹（只做重排，不检测 hoverTarget）
- 拖拽中 ScrollView 关闭滚动（`scrollDisabled`），防止自动滚动干扰

### 拖出面板 → 交接给主网格

**核心需求**：把 app 拖出面板外部，**面板立即关闭**，app **保持拖拽状态**进入主网格继续重排——整个过程中用户**不需要松手**。

详细实现见[第九节](#九拖出面板交接给主网格的技术实现)。

## 五、文件夹数据持久化

### 数据结构

```swift
// LayoutData 中的字段
var folders: [UUID: FolderInfo]

// FolderInfo
struct FolderInfo {
    let id: UUID
    var name: String          // 文件夹名称
    var appIDs: [String]      // 内部 app 的 bundleID 列表（有序）
    var isUserNamed: Bool     // 用户是否手动改名
}
```

### 布局中的占位

网格页面 (`LayoutData.pages`) 中用 `.folder(id: UUID)` 占位。
一个文件夹在网格中只占一个 slot，对应 `folders` 字典中的一条记录。

### 合并扫描 (mergeLayout)

应用扫描时，文件夹作为一个单元保留：
- 文件夹内的 app 不展开到主网格
- 已卸载的 app 从 `FolderInfo.appIDs` 中移除
- 文件夹为空时自动删除占位

### 存储位置

`~/Library/Application Support/AppLaunchpad/layout.json`

## 九、拖出面板交接给主网格——技术实现

> **功能**：把文件夹内容面板里的 app 拖到面板外部，面板立即关闭、app 保持拖拽状态进入主网格继续重排，全程不需要松手。

### 9.1 需求映射

| 时刻 | 行为 |
|------|------|
| 面板内按住并拖动 app | `dragSourceIndex` 设置，内部 make-way 生效 |
| **光标拖出面板边界** | 面板立即透明（`opacity 0`）→ 调用 `onDragOutHandoff`：从文件夹移除 app + 插回主网格 pages + `beginDrag` + `enterEditMode` |
| 继续移动（未松手） | 每次 `onChanged` → `onDragOutMove(location)` → 主网格 `updateDragTarget` → 浮动图标跟随 + make-way 让位 |
| **情况 1：松手时在面板外部** | `isDraggingOut=true` → `onDragOutEnd()` → `viewModel.endDrag()` 落位 + 关闭面板 |
| **情况 2：未拖出面板内部松手** | `isDraggingOut` 始终 false → 内部 `onReorder` 提交重排 |

### 9.2 架构：三回调交接

文件夹面板本身不直接操作主网格的 `DragState` / `DragController`，而是通过三个回调交给父级 `LaunchpadView` 接线：

```swift
// FolderExpandedView 的三个回调
var onDragOutHandoff: ((AppInfo, CGPoint) -> Void)?  // 第一次超出面板：移除 + 重插 + beginDrag
var onDragOutMove:   ((CGPoint) -> Void)?            // 交接后持续移动：updateDragTarget
var onDragOutEnd:    (() -> Void)?                    // 松手：endDrag + 关面板
```

```
┌──────────────────────────────────────────────────────────┐
│                     LaunchpadView                        │
│  ┌────────────────────────────────────────────────────┐ │
│  │         主网格 pagingView + floatingDragIcon        │ │
│  │  (dragState.isDragging → 浮动图标 + make-way)       │ │
│  └────────────────────────────────────────────────────┘ │
│                                                          │
│  ┌────────────────────────────────────┐ zIndex(1000)     │
│  │      FolderExpandedView overlay     │                  │
│  │  拖拽手势 → 检测超出 panel → 回调节点 │                  │
│  │          │          │         │     │                  │
│  │    handoff      move      end      │                  │
│  └──────────┼──────────┼─────────┼────┘                  │
│             │          │         │                        │
│   removeAppAndReinsert  │   endDrag +                    │
│   saveLayout, beginDrag │   expandedFolderID=nil         │
│             │          │                                  │
│         主网格 dragState 接管 → make-way + 浮动图标        │
└──────────────────────────────────────────────────────────┘
```

### 9.3 完整数据流（从文件夹到主网格）

```
Step 1: 面板内按下 app A 并拖动
  → dragGesture.onChanged
  → dragSourceIndex = idx, dragLocation = cursor

Step 2: 光标移出 panelFrame
  → panelFrameBox.frame.contains(location) == false
  → isDraggingOut = true
  → onDragOutHandoff(app, location)

Step 2.1: 父级回调（handoff）
  → FolderController.removeAppAndReinsert(app, fromFolder)
      ├─ 定位 .folder(folderID) 在 pages 中的页码 + 槽位
      ├─ removeApp(app)（若文件夹变空则删除）
      └─ pages[page].insert(.app(app), at: slot)  ← 插回主网格
  → saveLayout()
  → enterEditMode()
  → DragController.beginDrag(app, pageIndex: page, location)
      └─ dragState = DragState(isDragging: true, sourcePageIndex: page, ...)

Step 3: 面板 opacity 0（视觉关闭），但手势宿主 AppIconView 仍在层级中
  → 后续 onChanged → onDragOutMove(location)
  → 父级调用 viewModel.updateDragTarget(location)
  → 主网格 dragState.cursorSlot 更新 → pageItemsWithDrag 计算 make-way
  → floatingDragIcon 跟随光标

Step 4: 松手
  → dragGesture.onEnded
  → isDraggingOut → onDragOutEnd()
  → viewModel.endDrag()  ← 主网格 commit 重排
  → expandedFolderID = nil  ← ForkExpandedView 从层级移除
```

### 9.4 坑 1：`.allowsHitTesting(!isDraggingOut)` 杀死手势宿主

**现象**：拖出面板后 app 松手才回调，松手前没有反应。

**根因**：FolderExpandedView 的外层 ZStack 上有 `.allowsHitTesting(!isDraggingOut)`——一旦 `isDraggingOut=true`，整个视图树（含手势宿主 AppIconView）的命中测试被关闭，正在运行的高优先级手势**立即结束**。

**解决**：**仅靠 `.opacity(isDraggingOut ? 0 : 1)` 隐藏面板**，绝不用 `allowsHitTesting(false)`。opacity 不改变视图层级和命中测试，手势宿主保持存活。

### 9.5 坑 2：`@State var panelFrame: CGRect`——值类型快照捕获（核心漏洞）

**现象**：手势闭包里 `panelFrame` 永远是 `.zero`，拖出检测永不触发。

**根因**：SwiftUI 的 `@State` 对值类型（`CGRect`）的工作方式：

```
视图首次渲染 → body() 执行 → dragGesture 闭包创建
    ↓
闭包捕获 self → self.panelFrame = .zero（初始值）
    ↓
onPreferenceChange 更新 panelFrame → SwiftUI 重新执行 body()
    ↓
但已激活的手势闭包不会重建！它持有的仍是 .zero 快照
    ↓
panelFrame != .zero ← 永远不会为 true
```

**解决**：用**引用类型（class）包裹**。

```swift
// ❌ 手势闭包捕获的是 .zero 快照
@State private var panelFrame: CGRect = .zero

// ✅ 手势闭包捕获的是指针 → 始终读到最新 frame
private final class FrameBox { var frame: CGRect = .zero }
@State private var panelFrameBox = FrameBox()
```

`@State` 对于 class，存储的是对象的引用。修改 `panelFrameBox.frame` 不改变引用本身 → SwiftUI 不重新渲染 body → 但手势闭包每次 `onChanged` 时通过指针读到**最新值**。

同时改用 `onAppear` 主动计算 frame，不等 PreferenceKey 的异步回调：

```swift
.onAppear {
    let globalOrigin = geo.frame(in: .global).origin
    panelFrameBox.frame = CGRect(
        x: globalOrigin.x + (geo.size.width - panelW) / 2,
        y: globalOrigin.y + (geo.size.height - panelH) / 2,
        width: panelW, height: panelH
    )
}
```

### 9.6 坑 3：`removeApp` 不插回 pages → `beginDrag` 找不到 app

**现象**：拖出后 app 消失在主网格中（没有浮动图标，没有 make-way）。

**根因**：文件夹内的 app 不直接存在于 `LayoutData.pages` 中——它们在 `LayoutData.folders[folderID].appIDs` 里，页面只有 `.folder(folderID)` 占位。`FolderController.removeApp` 只把 app 从文件夹移走，但**没有重新插回 `pages`**。主网格的 `DragController.beginDrag` 用 `pages[pageIndex].firstIndex(of: .app(bundleID:))` 查找——找不到 → guard 失败 → 拖拽不启动。

**解决**：新增 `FolderController.removeAppAndReinsert`。

```swift
@discardableResult
func removeAppAndReinsert(_ bundleID: String, fromFolder folderID: UUID) -> Int {
    // 1. 先定位文件夹在主网格中的页码 + 槽位
    var insertPage = 0, insertSlot = pages.first?.count ?? 0
    for i in pages.indices {
        if let slot = pages[i].firstIndex(where: {
            if case .folder(let id) = $0, id == folderID { return true }
            return false
        }) { insertPage = i; insertSlot = slot; break }
    }
    // 2. 再执行移除（可能删除空文件夹）
    removeApp(bundleID, fromFolder: folderID)
    // 3. 插回原处（在文件夹占位之前或原位置）
    pages[insertPage].insert(.app(bundleID: bundleID), at: min(insertSlot, pages[insertPage].count))
    return insertPage
}
```

返回 `insertPage` 让父级传给 `beginDrag(pageIndex:)` 精确定位，避免 `currentPageIndex` 不一致时失败。
